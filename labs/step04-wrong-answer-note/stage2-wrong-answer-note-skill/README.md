# stage 2 — 2단계 파이프라인 Skill (인식 → 검수 → 오답노트)

> [stage 1](../stage1-wrong-answer-note-prompt/)에서 한 번에 처리하다 흔들리던 흐름을, **인식**과 **정리**를 두 개의 Skill로 쪼개고 그 사이에 **사람의 검수 자리**를 둡니다. 정형화의 진짜 가치가 형식 일관성 너머 **워크플로우 분할**에 있다는 메시지를 본 step에서 만들어 봅니다.

---

## 학습 목표

- 한 작업을 **하나의 Skill**로 처리할지 **여러 Skill의 파이프라인**으로 쪼갤지를 판단하는 감각을 익힙니다.
- 인식과 정리 사이에 **검수 자리**를 만들어, 잘못된 줄만 prompt로 재인식하고 채점·해설은 그대로 보존하는 흐름을 직접 만들어 봅니다.
- 두 Skill을 따로 다듬을 수 있다는 자산화의 효익(예: 해설 톤만 바꾸고 인식 규칙은 그대로)을 체감합니다.

---

## 사전 조건

- [stage 1](../stage1-wrong-answer-note-prompt/) 수료 (자유응답의 흔들림과 재인식 비용을 직접 본 상태)
- [step03 stage 2](../../../step03-voca-quiz/stage2-voca-quiz-skill/) 수료 권장 (멀티모달 + 출처 충실성 패턴 익힌 상태)
- Claude Pro 이상 요금제 + **Claude Desktop** + **Cowork** 사용 가능 환경 (엑셀 파일 생성·재읽기 필요)
- 자녀가 풀고 채점된 학습지 사진 1장 (stage 1과 같은 사진 권장 — 비교가 쉬워집니다)

---

## step01·02·03과의 차이 — 한 단계 위 설계

| 항목 | step01-weather | step02-file-classifier | step03-voca-quiz | **step04-wrong-answer-note** |
|------|--------------|----------------------|----------------|--------------------|
| Skill 개수 | 1~2개(독립) | 1개 | 1개 | **2개(파이프라인)** |
| 핵심 패턴 | 슬롯 채우기 | 옵션 1축 | 멀티모달 + 출처 충실성 | **검수 자리 + 분할** |
| 사람 개입 자리 | 호출 시 한 번 | 호출 시 한 번 | 호출 시 한 번 | **두 Skill 사이** (의도적) |
| "한 방에 처리" 욕구 | 자연스럽게 그렇게 됨 | 자연스럽게 그렇게 됨 | 자연스럽게 그렇게 됨 | **일부러 거부** |

step04 stage 2의 핵심 메시지는 "한 방에 처리하고 싶더라도 **검수 자리를 만드는 게 운영비용을 줄인다**"입니다.

## 파이프라인 한눈에

```
[채점된 학습지 사진]
       │
   ┌───▼─────────────┐
   │ Skill ①          │  사진 → 인식 결과 엑셀 (채점 X)
   │ quiz-recognize   │  - 학생답안·정답·학생표시·문제내용을 정직하게 옮김
   └───┬─────────────┘  - 정오 판정·해설은 절대 하지 않음
       │
       ▼
   [검수된 엑셀]  ◀──── ★ 부모 검수 자리 ★
       │              - 연필 답안·줄 그음·자체 표시 확인
       │              - 틀린 줄만 prompt로 재인식
       │              - 검수 단계에서 정오 컬럼까지 채움
       │
       │   ── 데이터의 단일 출처. 두 뷰가 여기서 갈라집니다 ──
       │
   ┌───┴───────────────────┐
   │                       │
   ▼                       ▼
┌────────────────────┐  ┌──────────────────────────┐
│ Skill ②             │  │ stage 3 Skill             │
│ wrong-answer-note  │  │ wrong-answer-html-report │
│ (마크다운 평문 뷰) │  │ (HTML 인쇄 뷰)           │
│ — 본 stage         │  │ — stage 3에서 호출       │
└──────────┬─────────┘  └─────────────┬────────────┘
           │                          │
           ▼                          ▼
[자녀가 혼자 읽는              [학원 워크북 톤의
 오답노트.md]                    HTML 1페이지]
```

> 두 뷰는 **서로를 거치지 않습니다** — 마크다운에서 HTML을 만드는 게 아니라, 같은 엑셀에서 각자 독립적으로 만듭니다. 한쪽 뷰만 필요하면 다른 쪽은 만들지 않아도 됩니다.

## 절차

### 1. Cowork 작업공간 열기

Claude Desktop을 실행하고 새 작업공간을 만들어 학습지 사진 파일을 둡니다.

### 2. Skill ① 「quiz-recognize」 생성

Claude의 Skills 메뉴에서 **새 Skill 만들기**를 선택합니다.

| 항목 | 예시 입력값 |
|------|-----------|
| 이름 | `채점지 인식` |
| 설명 | `채점된 학습지 사진을 받아 문항·학생답안·정답·학생표시를 엑셀로 정리한다. 정오 판정과 해설은 하지 않고 부모 검수에 맡긴다` |

Instructions에는 [`quiz-recognize/SKILL.md`](./quiz-recognize/SKILL.md)의 본문(frontmatter 제외)을 그대로 붙여넣습니다.

> Skill ①의 가장 중요한 규칙은 **"정오 판정·해설은 절대 하지 않는다"** 입니다. 이 한 줄이 검수 자리를 만드는 결정적 제약입니다 — Skill ①이 자동으로 채점까지 가버리면 stage 1과 똑같은 재인식 비용이 다시 발생합니다.

### 3. Skill ① 호출

작업공간에 학습지 사진을 두고 호출합니다.

```
[학습지 사진 첨부]
4학년 수학, 단원: 분수의 덧셈과 뺄셈. 인식해줘.
```

작업공간에 `quiz-recognized-<문제집>-<YYYY-MM-DD>.xlsx` 같은 파일이 생기면 성공입니다.

> 엑셀이 어렵다면 **CSV** 출력으로 전환할 수도 있습니다. SKILL.md의 출력 파일 확장자만 `.xlsx` → `.csv`로 바꾸면 동작합니다 — 비개발자가 보기엔 둘 다 표 형태로 열립니다.

### 4. ★ 검수 자리 ★

생성된 엑셀을 열어 다음을 확인합니다.

| 점검 항목 | OK 기준 |
|---------|--------|
| 모든 문항이 빠짐없이 들어왔는지 | 페이지의 문항 번호와 엑셀의 행 수가 일치 |
| 연필로 적은 학생답안이 학생답안 컬럼에 들어왔는지 | 자녀의 답이 그대로 들어있는지 글자 단위 비교 |
| 줄 그은 부분 처리 | 줄 그은 답이 학생답안에 남아있고 분석메모에 명시되었는지 |
| 자체 표시(★, ?, ○) | 학생표시 컬럼이 그 행에서 1로 마킹되었는지 |
| 정오·정답 컬럼 | **비어있어야 정상** (Skill ①이 채점하지 않음) |
| 분석메모 | 채점 기호와 답안 충돌이 있던 줄에는 메모가 적혀있는지 |

틀린 줄이 있으면 **그 줄만** 같은 대화에서 prompt로 재인식 요청합니다.

```
3번 문제의 학생답안이 비어있는데, 사진을 보면 자녀가 연필로 "5/12"라고 적었어. 엑셀의 그 행만 다시 채워줘.
```

```
7번 문제는 학생이 답에 줄을 그었어. 엑셀에 그대로 두고 분석메모에 "줄 그음"이라고 추가해줘.
```

> 핵심: **3번 한 줄을 고치자고 7번·12번의 채점·해설이 다시 흔들리지 않습니다** — 채점·해설은 다음 Skill에서 처리되기 때문입니다. 이게 stage 1과 가장 다른 부분입니다.

### 5. Skill ② 「wrong-answer-note」 생성

같은 작업공간에서 Skills 메뉴 → **새 Skill 만들기**.

| 항목 | 예시 입력값 |
|------|-----------|
| 이름 | `자녀 오답노트` |
| 설명 | `검수된 채점 엑셀을 받아 자녀가 혼자 읽는 오답노트 마크다운을 만든다. 친근한 말투, 학년 수준 용어, 단계별 풀이로 구성한다` |

Instructions에는 [`wrong-answer-note/SKILL.md`](./wrong-answer-note/SKILL.md)의 본문을 그대로 붙여넣습니다.

### 6. Skill ② 호출

검수가 끝난 엑셀을 첨부(또는 작업공간 파일을 지정)해 호출합니다.

```
[검수된 엑셀 첨부]
이 엑셀로 자녀 오답노트 만들어줘. 학년은 4학년, 과목은 수학, 단원은 분수의 덧셈과 뺄셈.
```

자녀 눈높이의 마크다운 오답노트가 출력됩니다 — 문항별 카드(문제 / 내가 쓴 답·맞는 답 / 왜 틀렸을까? / 이렇게 풀어 보자 / 기억 포인트) + 하단의 **오늘의 복습 포인트** 요약.

### 7. 호출 변형

**호출 A — 정답 표를 따로 첨부**

```
[검수된 엑셀 첨부]
[정답 표 사진 첨부]
첨부한 정답 표를 기준으로 채점하고 자녀 오답노트로 정리해줘.
```

**호출 B — 톤 조정**

```
[검수된 엑셀 첨부]
방금 만든 오답노트가 좀 길어. 1학년 동생이 읽을 정도로 짧고 쉽게 다시 만들어줘.
```

**호출 C — 단원 라벨**

```
[검수된 엑셀 첨부]
단원은 "분수와 소수". 단원 라벨 헤더에 그렇게 표시해줘.
```

**호출 D — 엑셀 미첨부 케이스**

```
오답노트 만들어줘.
```

(SKILL.md의 "엑셀 미첨부면 한 줄 답" 규칙이 동작하는지 확인)

## stage 1과 비교

stage 1에서 받은 자유응답과 본 stage의 결과를 늘어놓고 비교합니다.

| 비교 항목 | stage 1 (자유응답) | stage 2 (파이프라인 + 검수) |
|---------|------------------|--------------------------|
| 연필 답안 인식 | 자주 누락 | 인식 단계에서 한 번, 검수에서 한 번 — 두 단계 보호 |
| 줄 그은 부분 | 매번 다른 처리 | 학생답안에 보존 + 분석메모에 명시 |
| 자체 표시(★, ?) | 거의 무시 | 학생표시 컬럼으로 명시적 보존 |
| 한 줄 인식 오류 시 비용 | 모든 출력 재생성 | **그 줄만 prompt로 재요청**, 채점·해설은 보존 |
| 출력 형식(자녀 톤) | 회차마다 흔들림 | Skill ② instructions로 고정 |
| 다음 회차 재사용 | 매번 prompt 다시 작성 | 두 Skill 그대로 + 사진만 교체 |
| Skill 자산 다듬기 | 통째 prompt | **인식 규칙·해설 톤을 따로** 다듬을 수 있음 |

이 차이가 **"한 방에 처리 → 분할 + 검수 자리 + 자산 분리"** 의 효익입니다.

---

## 관찰 포인트

- **검수 자리는 "AI를 못 믿어서"가 아니라 "재인식 비용을 작게 만들기 위해"** 두는 자리입니다 — 한 줄 인식이 틀려도 채점·해설을 다시 받지 않아도 됩니다.
- **두 Skill의 instructions는 서로 독립적**입니다 — 자녀 학년이 바뀌면 Skill ②의 톤만 바꾸고, 새 문제집에 적응하려면 Skill ①의 인식 규칙만 다듬으면 됩니다.
- 같은 시리즈 안에서 step04만 **stage별 매체 요건이 다릅니다** (stage 1은 일반 챗봇, stage 2·3은 Cowork) — 비개발자에게 "Skill의 가치가 커질수록 매체 요건도 함께 올라간다"는 신호입니다.

## 트러블슈팅

| 증상 | 점검 |
|------|------|
| Skill ①이 정오 판정까지 해버린다 | Instructions 상단의 "정오 판정·해설은 절대 하지 않는다" 규칙이 살아있는지 확인. 같은 사진에서 반복되면 규칙을 한 번 더 강조 |
| 엑셀이 안 생기고 텍스트로만 응답한다 | Cowork 환경인지 확인 (claude.ai 웹·일반 챗봇은 파일 생성 불가). Claude Pro 이상 요금제 필요 |
| 연필 답안이 자주 누락된다 | 사진을 더 밝고 선명하게 다시 촬영. SKILL.md의 "학생이 연필로 적은 답안과 표시도 모두 인식한다" 규칙 위치 확인 |
| 검수 후 재인식 요청에 다른 행까지 다시 쓴다 | "엑셀의 N번 행만" 같이 범위를 명시. 그래도 그러면 새 대화에서 검수된 엑셀로 Skill ②를 직접 호출 |
| Skill ②가 자녀 톤이 아니다 | Instructions의 "친근하고 따뜻하게", "'틀렸다' 반복 강조 금지" 규칙 확인. "1~2학년 수준으로 더 쉽게 다시 만들어줘" 식 한 줄 추가 호출도 효과적 |
| 정답 컬럼이 비어있어 채점이 안 된다 | Skill ②에 정답 표를 사진으로 추가 첨부하거나 prompt 본문에 정답 리스트를 텍스트로 붙여넣기 |

## 막혔다면 — 동작 가능한 참고 Skill

본 stage의 두 Skill은 그대로 들어 있습니다.

- [`quiz-recognize/SKILL.md`](./quiz-recognize/SKILL.md) — Skill ① (사진 → 인식 결과 엑셀, 채점 X)
- [`wrong-answer-note/SKILL.md`](./wrong-answer-note/SKILL.md) — Skill ② (검수된 엑셀 → 자녀용 오답노트)

따라하다 막히면 두 SKILL.md의 instructions를 본인 Skill에 그대로 복사해 비교해 볼 수 있습니다. Claude Desktop의 Skills에서 디렉토리를 그대로 등록해 직접 호출해 볼 수도 있습니다.

## Project로도 운영하기

Skill instructions는 **Claude Project**의 custom instructions에도 그대로 들어갑니다. 다만 본 step은 **두 Skill 파이프라인**이라 운영 형태가 step03와 다릅니다.

| 운영 패턴 | 형태 |
|---------|------|
| Skill 2개 (권장) | 한 작업공간 안에서 Skill ① 호출 → 엑셀 검수 → Skill ② 호출. 자산화에 가장 자연스러움 |
| Project 2개 | "채점지 인식" Project + "자녀 오답노트" Project. 모바일에서 자녀 옆에 있을 때 빠른 진입에 유리 |
| Project 1개 + 단계 안내 | 한 Project의 instructions에 두 단계를 모두 넣고 사용자가 "1단계", "2단계" 키워드로 호출 — 단순하지만 검수 자리가 흐려질 수 있음 |

자녀 옆에서 모바일로 사진 찍어 즉시 진행하는 흐름이라면 **Project 2개**가 자연스럽고, 작업공간에서 자산을 누적·관리하는 흐름이라면 **Skill 2개**가 자연스럽습니다.
