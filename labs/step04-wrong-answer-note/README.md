# step04-wrong-answer-note ― 자녀 채점지 오답노트

> 자녀가 푼 학습지 채점 사진을 받아 **자녀가 혼자 읽는 오답노트**까지 만든 뒤, 학원 워크북 톤의 **인쇄용 HTML 리포트**까지 한 번에 잇는 풀 코스 실습. step01~03에서 만든 패턴을 모아 **다단계 파이프라인 + 사람의 검수 자리**라는 한 단계 깊은 Skill 설계를 익힙니다.

---

## 학습 목표

- 한 작업을 **하나의 Skill**로 모두 처리할지, **여러 Skill의 파이프라인**으로 쪼갤지를 판단하는 감각을 익힙니다.
- "정형화의 진짜 가치는 형식 일관성 너머 **워크플로우 분할**에 있다" ― 인식과 정리 사이에 일부러 **검수 자리**를 만드는 패턴을 직접 만들어 봅니다.
- 인쇄용 HTML 디자인까지 **프롬프트로 생성**하는 흐름으로 시리즈의 [진행 원칙](../README.md#진행-원칙--프롬프트로만-진행합니다)을 마지막까지 밀어붙입니다.

---

## 실제 활용 시나리오

부모가 자녀의 학습지 채점 결과를 사진으로 찍어 자녀가 스스로 복습할 수 있는 오답노트를 만들 때 자주 겪는 어려움을 출발점으로 합니다.

| 기존 방식의 어려움 | Skill 파이프라인으로 해결 |
|------------------|---------------------|
| 사진을 한 번에 던지면 AI가 연필 답안을 누락하거나 줄 그은 곳을 오인식 | **인식 단계와 정리 단계를 분리** ― 인식만 먼저 끝내고 부모가 검수한 뒤 다음 단계로 |
| 한 번에 채점·해설까지 받으면, 인식이 틀렸을 때 다시 처음부터 (재인식 비용 큼) | 검수 단계에서 잘못된 줄만 prompt로 재인식 ― 채점·해설은 그대로 보존 |
| 자녀 눈높이에 맞춘 따뜻한 말투·단계별 풀이가 매번 흔들림 | "자녀가 혼자 읽는다"는 톤 규칙을 Skill instructions로 고정 |
| 종이로 출력해 자녀에게 주려면 평문 텍스트로는 모양이 안 남 | 검수된 엑셀 → 학원 워크북 톤의 인쇄용 HTML 1페이지 (디자인 슬롯 템플릿은 prompt로 만들어 동봉, 데이터는 엑셀에서) |

> 본 step의 원형은 사용자가 Google Gems 3개(문제분석 → 오답노트 → 리포팅)로 운영하던 자녀 학습 보조 도구입니다. 본 실습에서는 이를 Claude Skill 파이프라인 + 디자인 프롬프트로 옮기면서 **검수 자리**라는 학습 메시지를 명시적으로 드러냅니다.

## stage 구성

| stage | 디렉토리 | 단계 | 학습 포인트 |
|-------|---------|------|------------|
| 1 | [stage1-wrong-answer-note-prompt/](./stage1-wrong-answer-note-prompt/) | 챗봇 자유응답 reference | 채점 사진 한 장 + "오답노트 만들어줘" 자유응답 ― OCR 오인식·출력 형식 흔들림·검수 자리 부재로 **재인식 비용**이 누적되는 것을 체감 |
| 2 | [stage2-wrong-answer-note-skill/](./stage2-wrong-answer-note-skill/) | 2단계 파이프라인 Skill | Skill ① 사진 → 인식 결과 엑셀(채점 X) → 부모 검수 → Skill ② 검수된 엑셀 → 자녀용 오답노트 마크다운. **검수 자리를 일부러 둔다**는 메시지 |
| 3 | [stage3-wrong-answer-note-report/](./stage3-wrong-answer-note-report/) | 인쇄용 HTML 리포트 | 검수된 엑셀 → 학원 워크북 톤의 단일 HTML. 슬롯 템플릿(`wrong-answer-note-template.html`) + 채워진 예시(`classical.html`) 동봉. Skill이 스칼라 슬롯 + **PROBLEMS·SELF_CHECK 블록 반복 마커**로 가변 문항 처리. **데이터(엑셀)와 디자인(슬롯 템플릿)의 분리** ― 마크다운 뷰와 HTML 뷰는 같은 엑셀에서 갈라지는 평행 뷰 |

## step01~03과의 차이 ― Skill 설계 패턴이 한 단계 더

| step | 핵심 Skill 패턴 |
|------|---------------|
| step01-weather | 텍스트 형식 통일 + 사전 동봉 HTML 템플릿 슬롯 채우기 |
| step02-file-classifier | 옵션 1축 분기 |
| step03-voca-quiz | 멀티모달 + 출처 충실성 + 외부 도구 직접 링크 |
| **step04-wrong-answer-note** | **다단계 파이프라인 + 사람의 검수 자리 + 데이터·뷰 분리(엑셀 ↔ 마크다운/HTML 평행 뷰)** |

step01~03이 "Skill 하나의 완성도"를 끌어올리는 패턴이라면, step04는 "여러 Skill을 어떻게 잇고, 어디에 사람의 검수 자리를 둘 것인가"라는 한 단계 위 설계 감각을 다룹니다.

---

## 매체 안내

| stage | 필요 매체 |
|-------|---------|
| 1 | 이미지 업로드가 가능한 환경 (claude.ai 웹·Claude Desktop 모두 OK) |
| 2 | Claude Desktop + **Cowork** (엑셀 파일 생성·재읽기 필요) |
| 3 | Claude Desktop + **Cowork** (HTML 파일 저장 필요), 인쇄·PDF 저장 가능한 브라우저 |

stage 1만 일반 챗봇 환경에서 가능하고, stage 2·3은 Cowork이 필요합니다 ― step02·step03와 다르게 stage별 매체 요건이 갈립니다.

---

## 선정 근거

ADR-0001이 별도 이슈로 미뤘던 **"Gems 기반 AI 오답노트를 Claude Skill로 재설계"** 항목을 본 step에서 다룹니다. 사용자가 실제 운영하던 3-Gem 흐름(문제분석 → 오답노트 → 리포팅)을 Claude Skill 파이프라인으로 옮기되, **인식과 정리 사이의 검수 자리**라는 학습 메시지를 본 시리즈의 마지막 step에서 정면으로 드러냅니다.

---

## 시리즈 종료 ― step04를 마치고 나면

- step01에서 **텍스트 형식**을 잠갔고
- step02에서 **옵션**으로 한 Skill을 여러 상황에 펼쳤고
- step03에서 **이미지 입력 + 출처 충실성 + 외부 도구**로 Skill의 출력 가치를 끌어올렸고
- step04에서 **여러 Skill을 잇고 검수 자리를 만드는** 설계 감각까지 도달합니다.

여기까지가 본 시리즈가 다루는 비개발자 대상 Skill 설계의 기본기입니다.
