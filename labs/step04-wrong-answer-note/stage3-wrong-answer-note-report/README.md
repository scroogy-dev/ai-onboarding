# stage 3 — 인쇄용 HTML 리포트 (학원 워크북 톤)

> [stage 2](../stage2-wrong-answer-note-skill/)에서 검수한 **채점 결과 엑셀**을 학원 워크북 톤의 **인쇄용 HTML 1페이지**로 변환합니다. **슬롯 박힌 템플릿**([`wrong-answer-html-report/wrong-answer-note-template.html`](./wrong-answer-html-report/wrong-answer-note-template.html))을 Skill이 채우고, **데이터(엑셀)와 디자인(템플릿)을 분리**합니다 — 마크다운 뷰는 거치지 않습니다.

---

## 학습 목표

- 검수된 채점 결과 엑셀을 학원 워크북 톤의 **인쇄·PDF 친화** HTML 1페이지로 변환합니다.
- **데이터(엑셀)와 디자인(슬롯 템플릿)을 분리**해 다루는 사고를 만들어 봅니다 — 엑셀이 데이터의 단일 출처이고, 마크다운 뷰와 HTML 뷰는 그 위에서 평행으로 갈라집니다.
- step01 stage 3와 같은 **슬롯 채우기 패턴**을 한 단계 발전시킵니다 — 가변 개수의 문항 카드를 위한 **블록 반복 마커**까지.

---

## 사전 조건

- [stage 2](../stage2-wrong-answer-note-skill/) 수료 — **검수가 끝난 채점 결과 엑셀** 1편을 손에 들고 있는 상태 (자녀용 마크다운은 따로 만들어 두었거나, 만들지 않았어도 무방)
- Claude Pro 이상 요금제 + **Claude Desktop** + **Cowork** (HTML 파일 저장 필요)
- 인쇄·PDF 저장 가능한 브라우저 (Chrome·Edge·Safari 모두 OK)

## 동봉 자산

| 파일 | 역할 |
|------|------|
| [`wrong-answer-html-report/wrong-answer-note-template.html`](./wrong-answer-html-report/wrong-answer-note-template.html) | **슬롯 템플릿**. `{{...}}` 스칼라 슬롯 + `<!-- PROBLEMS:START/END -->`·`<!-- SELF_CHECK:START/END -->` 블록 반복 마커. Skill이 이 파일을 읽고 채움 |
| [`wrong-answer-html-report/SKILL.md`](./wrong-answer-html-report/SKILL.md) | 슬롯 채우기·블록 반복 처리 절차 10단계 instructions |

## step01 stage 3와의 차이

| 항목 | step01 stage 3 (날씨) | step04 stage 3 (오답노트) |
|------|---------------------|------------------------|
| 슬롯 형태 | 스칼라 슬롯만(`{{city}}`·`{{temperature}}` 등 9개 고정) | 스칼라 슬롯 + **블록 반복 마커**(`<!-- PROBLEMS:START/END -->` 등) |
| 데이터 형태 | 도시 1개·필드 9개 고정 | 문항 N개(가변)·자체 체크 M개(0~여러)·복습 포인트 |
| 데이터 출처 | 자유응답 텍스트 (stage 2 Skill 출력) | **검수된 엑셀** (stage 2 Skill ① 출력 + 부모 검수) |
| 출력 변동 | 매번 같은 모양 | 문항 수가 회차마다 다름·자체 체크 섹션 자체가 사라질 수 있음 |
| 동봉 자산 | 슬롯 템플릿 + Skill | 슬롯 템플릿 + Skill + **채워진 예시** |
| 학습 메시지 | 슬롯 채우기 | 슬롯 채우기 + **블록 반복 + 데이터·뷰 분리(엑셀 ↔ 마크다운/HTML 평행)** |

step01이 **고정 슬롯의 정형화**라면, 본 stage는 **가변 데이터를 위한 블록 반복 마커**까지 다룹니다.

## 슬롯 템플릿 들여다보기

`wrong-answer-note-template.html`의 핵심 구조는 다음 세 부분입니다.

```
<head>
  ... 폰트·CSS·@media print 모두 그대로
</head>
<body>
  <article class="page">
    <!-- 스칼라 슬롯들: 학생·학년·과목·단원·총평·통계 4개 등 -->
    ...

    <!-- PROBLEMS:START -->
      <!-- PART · I 섹션 헤더 (한 번만) -->
      <article class="problem">
        ... 슬롯 박힌 한 카드 (Skill이 데이터 행 수만큼 복제)
      </article>
    <!-- PROBLEMS:END -->

    <!-- SELF_CHECK:START -->
      <!-- PART · II 섹션 헤더 (한 번만) -->
      <article class="problem self-check">
        ... 슬롯 박힌 한 카드 (Skill이 데이터 행 수만큼 복제)
      </article>
    <!-- SELF_CHECK:END -->

    <!-- 닫는 PART · III + footer 슬롯 -->
  </article>
</body>
```

**Skill이 처리하는 두 가지 일**

1. `{{slot}}` → 단일 값 치환 (스칼라 슬롯)
2. `<!-- BLOCK:START -->` ... `<!-- BLOCK:END -->` → 안의 `<article>` 카드를 데이터 행 수만큼 복제하면서 슬롯 채움. 데이터가 0건이면 블록 통째로 제거

전체 슬롯 목록과 각 슬롯의 기본값은 [`wrong-answer-html-report/SKILL.md`](./wrong-answer-html-report/SKILL.md)의 "슬롯 매핑" 섹션을 참조하세요.

## 데이터 구조 원칙 — 엑셀이 데이터, 마크다운·HTML은 평행 뷰

**데이터의 단일 출처는 엑셀**입니다. 본 stage는 그 엑셀에서 직접 HTML 뷰를 만들고, stage 2의 `wrong-answer-note` Skill은 같은 엑셀에서 마크다운(평문) 뷰를 만듭니다 — 둘은 **형제 뷰**이며 한쪽이 다른 쪽을 거치지 않습니다.

```
                ┌──────────────┐
                │ 검수된 엑셀  │  ← 데이터의 단일 출처
                └──────┬───────┘
                       │
          ┌────────────┴────────────┐
          ▼                         ▼
   wrong-answer-note         wrong-answer-html-report
   (마크다운 평문 뷰)         (HTML 인쇄 뷰)
```

| 매체 | 책임 |
|------|------|
| 엑셀 (데이터) | 문항·학생답안·정답·학생표시·정오·개념태그·분석메모 + 메타(분석일·학년·과목·단원·총문항수). 모든 뷰의 단일 출처 |
| 슬롯 템플릿 (디자인) | 인쇄용 톤·레이아웃·CSS·섹션 구조·슬롯 위치 |
| 호출 prompt | 엑셀에 없는 필드(학생 이름·튜터·학원 브랜드 등). 안 주면 SKILL.md의 기본값 |
| Skill의 자체 생성 | 자녀 친화 해설(왜 헷갈렸을까·이렇게 풀어 보자·기억 포인트) + `{{exec_summary_html}}` 총평. **새로운 사실은 만들지 않고 엑셀 본문 근거로** |

이 분리를 지키면 **엑셀만 누적**해도 충분히 가족의 학습 자산이 되고, **디자인을 다른 톤으로 바꿔도** 엑셀은 그대로입니다. 마크다운 뷰를 만든 회차에서도 본 Skill은 마크다운을 참조하지 않고 엑셀에서 직접 HTML을 만듭니다 — **두 뷰의 독립**이 핵심입니다.

## 절차

### 1. Cowork 작업공간 준비

Claude Desktop을 실행하고 새 작업공간(또는 stage 2와 같은 작업공간)에 다음 두 파일을 둡니다.

- stage 2에서 검수한 `quiz-recognized-<문제집>-<YYYY-MM-DD>.xlsx`
- 본 stage의 슬롯 템플릿 [`wrong-answer-note-template.html`](./wrong-answer-html-report/wrong-answer-note-template.html)

> 자녀용 마크다운은 본 Skill의 입력이 **아닙니다** — 이미 만들어 두었어도 첨부할 필요 없습니다.

### 2. 채워진 예시 미리 보기 (선택)

[`classical.html`](./classical.html)을 브라우저에서 열어 슬롯이 모두 채워졌을 때의 결과 톤을 먼저 봅니다. step01 stage 3의 `example-output.html`과 같은 역할입니다 — 학습자가 결과의 형태를 미리 알고 작업하면 따라가기 쉽습니다.

### 3. Skill 생성

Claude의 Skills 메뉴 → **새 Skill 만들기**.

| 항목 | 예시 입력값 |
|------|-----------|
| 이름 | `오답노트 HTML 리포트` |
| 설명 | `검수된 채점 결과 엑셀과 동봉된 슬롯 템플릿을 받아, 같은 톤의 인쇄용 단일 HTML 1페이지를 작업공간에 저장한다` |

Instructions에는 [`wrong-answer-html-report/SKILL.md`](./wrong-answer-html-report/SKILL.md)의 본문(frontmatter 제외)을 그대로 붙여넣습니다.

### 4. 호출

```
[quiz-recognized-quiz-2026-05-09-P12.xlsx 첨부]
학생: 김민준, 학원: Atrium Academy, 튜터: 이서연 선생님, 총문항수: 5
```

작업공간에 `wrong-answer-note-html-수학-2026-05-09.html` 같은 파일이 생기면 성공입니다. 결과를 [`classical.html`](./classical.html)과 늘어놓고 비교하면 톤이 같은지 확인할 수 있습니다.

### 5. 결과 확인 및 인쇄

생성된 HTML 파일을 운영체제의 파일 탐색기에서 더블클릭(또는 우클릭 → 열기)해 **브라우저로 엽니다**. 학원 워크북 톤의 1페이지 리포트가 보이면 OK입니다.

브라우저에서 `Ctrl/Cmd + P` → 대상 `PDF로 저장` → A4 세로 → 여백 기본값. PDF가 생기면 자녀 책상 위에 출력해 두거나 학습 폴더에 누적해 보관할 수 있습니다.

### 6. 호출 변형

**호출 A — 학원·튜터 비공개 운영**

```
[엑셀 첨부]
학생: 김민준, 학원·튜터는 비워둬.
```

→ profile의 학생만 채우고 학원 브랜드·튜터는 SKILL.md의 기본값(`Atrium · Academy` 등) 유지.

**호출 B — 자체 체크 문항이 0건**

→ Skill이 `<!-- SELF_CHECK:START -->` ~ `<!-- SELF_CHECK:END -->` 블록을 통째로 제거. PART · II 섹션 자체가 결과 HTML에 등장하지 않습니다.

**호출 C — 정답 표를 따로 첨부**

```
[검수된 엑셀 첨부]
[정답 표 사진 첨부]
엑셀의 정답 컬럼이 비어있는 행은 첨부한 정답 표를 기준으로 채워줘.
```

→ Skill이 정답을 보강한 뒤 처리 범위(`정오: false` ∪ `학생표시: 1`)를 결정.

**호출 D — 엑셀 미첨부**

```
HTML 리포트 만들어줘.
```

→ SKILL.md의 "엑셀 미첨부면 한 줄로 답한다" 규칙이 동작하는지 확인.

## 디자인을 다듬거나 톤을 추가하는 두 가지 길

### 길 A — 같은 디자인을 다음 회차에도 그대로

받은 HTML이 마음에 들면 슬롯 템플릿(`wrong-answer-note-template.html`)을 그대로 두고 매주 검수된 엑셀만 새로 받아 호출합니다. **추가 작업 0**.

### 길 B — 새 디자인 톤 추가 (프롬프트로 디자인)

다른 톤(미니멀·모던·과학노트 등)을 더 두고 싶다면 디자인 prompt로 새 슬롯 템플릿을 만들고 같은 디렉토리에 추가합니다.

```
첨부한 wrong-answer-note-template.html과 동일한 슬롯 이름·블록 마커를 유지하되, 디자인을 미니멀·모던 톤(흑백·여백 큰·시스템 sans-serif)으로 다시 만들어줘. 외부 리소스 없이 내장 CSS만. 파일명은 minimal-template.html.
```

받은 템플릿을 `wrong-answer-html-report/minimal-template.html`로 저장하면, 다음 회차부터 호출 시 `슬롯 템플릿: minimal-template.html` 같이 지정해 같은 Skill로 다른 톤을 받을 수 있습니다.

> 새 톤도 **같은 슬롯 이름과 블록 마커**를 유지하면 Skill을 다시 만들 필요 없이 동작합니다. 디자인만 갈아끼우는 셈입니다 — 데이터·뷰 분리의 효익이 가장 직접적으로 드러나는 자리.

## 관찰 포인트

- **데이터(엑셀)와 뷰(마크다운/HTML) 분리** — 엑셀이 사실의 단일 출처. 마크다운 뷰와 HTML 뷰는 같은 엑셀에서 각자 만들어지며 서로를 참조하지 않습니다. 한쪽 뷰의 디자인을 바꿔도 다른 뷰는 그대로입니다.
- **슬롯 + 블록 반복**이 step01의 단순 슬롯 채우기보다 한 단계 위 패턴입니다. 데이터의 개수가 가변인 모든 곳에서 같은 패턴을 쓸 수 있습니다.
- **Skill이 새 사실을 창작하지 않습니다** — 엑셀에 없는 필드(다음 학습 권장 등)는 빈 칸으로 둡니다. AI가 자녀 학습 정보를 임의로 만드는 것을 방지합니다.
- **자녀 친화 해설은 예외** — 학년·문제·답·분석메모를 근거로 본 Skill이 자체 생성합니다. 마크다운 뷰가 만들던 해설을 HTML 뷰가 평행으로 다시 만든다는 의미고, 두 뷰가 독립적이라는 사실의 자연스러운 귀결입니다.

## 트러블슈팅

| 증상 | 점검 |
|------|------|
| HTML 파일이 안 생기고 화면에만 출력된다 | Cowork 작업공간인지 확인 (claude.ai 웹·일반 챗봇은 파일 저장 불가). prompt에 `작업공간에 저장`이 들어있는지 |
| 결과 HTML에 `{{...}}` 이 그대로 남았다 | Skill instructions의 "5단계 — 스칼라 슬롯 채우기"가 누락됐는지. 같은 슬롯 이름이 정확히 매칭되는지 (대소문자·언더스코어 포함) |
| 문항 카드가 1개만 나오고 나머지가 누락 | "6단계 — PROBLEMS 블록 반복" 처리가 빠짐. SKILL.md의 해당 단계를 다시 강조해 호출 |
| 자체 체크 섹션이 안 사라지고 빈 카드가 보인다 | "7단계 — SELF_CHECK 블록 반복"의 "0건이면 블록 통째 제거" 규칙이 적용되지 않음. Skill instructions 점검 |
| 인쇄 시 페이지가 잘린다 | 결과 HTML에 `@media print` 규칙이 그대로 들어있는지 확인. 슬롯 템플릿의 `<style>` 블록을 통째로 보존했는지 |
| 폰트가 시스템 sans-serif로 보인다 | 외부 폰트 로딩(`<link href="...fonts.googleapis...">`)이 결과 HTML에 포함되었는지. 오프라인 인쇄가 필요하면 prompt에 `외부 폰트 로딩 제거하고 시스템 폰트 fallback만`을 추가 |
| 엑셀에 없는 필드가 멋대로 채워졌다 | SKILL.md의 "엑셀에 없는 정보를 창작해 채우지 않는다" 규칙 확인. 같은 규칙을 호출 prompt에 한 번 더 강조 |
| 정답률이 100%로 잘못 나온다 | 엑셀의 `정오` 컬럼이 검수에서 제대로 채워졌는지 확인. 검수 단계에서 빈 칸이 남았다면 Skill이 정답으로 오판할 수 있음. 호출에 `총문항수: <N>`을 명시적으로 보내면 안전 |

## 시리즈 마무리 — step04를 마치고 나면

- **stage 1**: 한 사진에 모든 일을 묶었을 때의 재인식 비용을 봤습니다.
- **stage 2**: **2개의 Skill로 쪼개고 사이에 검수 자리를 둔** 파이프라인을 만들었습니다.
- **stage 3**: **슬롯 + 블록 반복으로 가변 데이터를 다루고**, **데이터(엑셀)와 디자인(슬롯 템플릿)을 분리**하는 흐름까지 도달했습니다. 마크다운 뷰와 HTML 뷰는 같은 엑셀에서 각자 만들어지는 형제 뷰입니다.

step01의 텍스트 형식 통일 + 단순 슬롯 채우기에서 시작해, step04의 다단계 파이프라인 + 검수 자리 + 가변 데이터 슬롯 + 데이터·뷰 분리까지 — 본 시리즈가 다루는 비개발자 대상 Skill 설계의 기본기는 여기서 마무리됩니다.
