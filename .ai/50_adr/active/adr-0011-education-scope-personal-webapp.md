# ADR-0011: 교육 범위 경계 이동 ― 개인용 로컬 HTML·자바스크립트 웹앱까지 확장

- **상태**: Accepted
- **결정일**: 2026-08-23
- **연관 이슈**: [Issue #50](https://github.com/scroogy-dev/ai-onboarding/issues/50)
- **영향 범위**: `docs/basics.md` 「결과물의 성격」 절, `docs/index.md`, `docs/connect/mcp-servers.md`, `slides/slides.md` 27번 슬라이드, `.ai/40_domain/glossary.md` 「애플리케이션」 항목
- **연관 ADR**: [ADR-0008](adr-0008-determinism-explicit-visualization-comparison-table.md) (결과물 3종 분류의 끝점을 재정의), [ADR-0001](adr-0001-practice-tool-scope-and-stage-model.md) (3단계 학습 모델은 그대로), [ADR-0005](adr-0005-core-message-non-developers-make-software.md) (본질 메시지의 연장선)

## 배경 (Context)

ADR-0008 결정 2는 결과물을 `1회성 프롬프트` / `에이전트 스킬` / `애플리케이션` 3종으로 나누고, `애플리케이션`을 **본 교육이 직접 제작하지 않는 비교 기준**으로 배치했다. 학습자가 "내가 만드는 에이전트 스킬은 결정성·비용 두 축 위에서 어디에 있는가"를 두 끝점 사이에서 인지하게 하려는 장치였다.

이 배치의 전제는 애플리케이션 제작에 설계·코드·테스트라는 엔지니어링 비용이 든다는 것이었다. 그런데 에이전트가 코드 작성을 거들면서, 비개발자도 파일 하나짜리 웹앱 정도는 만들어 볼 수 있는 상황이 됐다. 끝점 전체를 범위 밖으로 두면 교육이 다룰 수 있는 것을 다루지 않게 된다.

동시에 끝점 전체를 범위 안으로 들이면 다른 문제가 생긴다. 다수 사용자·서버·배포가 따라오는 순간 결정적 신뢰성과 유지보수가 필요해져 90분 교육이 감당할 수 없다.

---

## 결정 (Decision)

### 1. 경계를 애플리케이션 안쪽으로 옮긴다

`애플리케이션`을 통째로 범위 밖에 두던 배치를 폐기하고, 애플리케이션 안에서 경계를 긋는다.

**범위 안**: 개인용이면서 HTML·자바스크립트만으로 동작하는 웹앱. 내 컴퓨터에서 파일 하나를 브라우저로 열면 동작하는 것을 뜻한다.

**범위 밖**: 아래 셋 중 하나라도 해당하면 범위 밖이다.

| 구분 | 범위 밖인 이유 |
|------|----------------|
| 여러 사람이 함께 쓰는 앱 | 개인용이 아니게 되는 순간 결정적 신뢰성과 유지보수 부담이 따라온다 |
| HTML·자바스크립트만으로 동작하지 않는 앱 | 별도 서버나 설치·빌드 도구가 필요하면 개발 환경을 갖추는 일부터 다른 이야기가 된다 |
| 내 컴퓨터를 벗어나 웹사이트로 배포하는 일 | 다른 사람이 접속할 주소를 만들어 올리면 호스팅·접근 권한을 다루게 된다 |

### 2. 세 번째 항목은 낱말로 이름 붙이지 않고 대비로 서술한다

배포 행위에 「퍼블리싱」 같은 낱말을 붙이지 않는다. 비개발자 독자에게 새 용어를 하나 더 외우게 하는 대신, **로컬 사용과 웹사이트 배포의 대비**로 어디까지가 범위 안인지를 문장으로 적는다.

### 3. ADR-0001의 3단계 학습 모델은 건드리지 않는다

이 결정이 바꾸는 것은 ADR-0008의 **결과물 형태 분류**에서 끝점의 경계뿐이다. `챗봇 사용` → `프롬프트 재활용` → `에이전트 활용` 사다리는 그대로이며, 교육의 초점도 여전히 비개발자가 직접 만드는 에이전트 스킬이다. 개인용 웹앱은 사다리의 새 칸이 아니라 끝점 쪽으로 넓힌 여유 공간이다.

ADR-0008 결정 2의 「두 좌표축」 구조도 유지된다. 두 분류는 여전히 차원이 다르고 서로 대체하지 않는다.

### 4. 결과물 검토 책임은 앱으로 갈수록 무거워진다

개인용이라도 앱에 가까워질수록 읽고 이해하고 검토하는 책임(`docs/index.md` 메타 원칙 ③ `#meta-principles`)이 함께 커진다는 것을 본문에 함께 적는다. ADR-0006이 정한 실습 2원칙(프롬프트로만 진행, 결과물 검토·이해 의무) 중 후자의 연장이다.

## 고려한 대안 (Alternatives considered)

### 대안 A. 애플리케이션 전체를 범위 밖으로 유지

- **장점**: ADR-0008 결정 2를 그대로 유지. 두 끝점 구조가 선명하다.
- **기각 사유**: 에이전트가 코드 작성을 거드는 현재 상황에서 비개발자가 실제로 만들어 볼 수 있는 것을 교육이 다루지 않게 된다.

### 대안 B. 애플리케이션 전체를 범위 안으로 편입

- **장점**: 경계 서술이 필요 없어 단순하다.
- **기각 사유**: 다수 사용자·서버·배포가 따라오면 결정적 신뢰성과 유지보수가 필요해 90분 교육의 범위를 벗어난다. 비교표의 끝점이 사라져 ADR-0008의 인지 장치도 무너진다.

### 대안 C. 「퍼블리싱」을 용어로 도입해 범위 밖을 지칭

- **장점**: 세 번째 범위 밖 항목을 한 낱말로 부를 수 있다.
- **기각 사유**: 비개발자 독자에게 외울 용어를 늘린다. 프로젝트 규칙인 전문 용어 최소화와 어긋나며, 대비 서술로 같은 내용을 전달할 수 있다.
