# ADR-0010: 2부(도구·데이터 연결) 신설 — 같은 사이트 안에서 범위 축 확장

- **상태**: Accepted
- **결정일**: 2026-07-28
- **연관 이슈**: [Issue #49](https://github.com/scroogy-dev/ai-onboarding/issues/49)
- **연관 ADR**:
    - [ADR-0001](adr-0001-practice-tool-scope-and-stage-model.md) — 실습 도구 범위(Claude 단독)·3단계 모델. **대체가 아니라 확장 대상**
    - [ADR-0002](adr-0002-publishing-structure-docs-ssot-slides-derivative.md) — docs SSoT / slides 후행 파생. 2부도 같은 구조를 따르며 slides는 후속 이슈
    - [ADR-0005](adr-0005-core-message-non-developers-make-software.md) — 비개발자 경계. 2부의 "이용까지만" 선을 긋는 근거
- **영향 범위**: `docs/connect/`(신규 3페이지), `mkdocs.yml`(nav 부 구분), `docs/basics.md`·`docs/intro.md`(1부 접합부), `docs/security-guide.md`("외부 연결" 절 신설)

---

## 배경 (Context)

ADR-0001은 실습 도구를 Claude 단독으로 고정했고, `docs/basics.md`는 외부 컨텍스트 항목에서 "**본 강의의 범위 밖**입니다. … MCP 서버 설치·등록, RAG 내부 구조·구현 패턴 모두 다루지 않습니다"라고 선언해 왔다. 이 선언의 취지는 **온보딩 필수 분량을 지키는 것**이었지, MCP가 비개발자에게 불필요하다는 판단이 아니었다.

그 사이 전제가 바뀌었다.

1. **진입 장벽이 낮아졌다** — 기본 커넥터(GitHub·Atlassian 등)는 설정 파일 편집 없이 UI에서 로그인·승인만으로 연결된다. "설치·등록"이라는 단어가 전제하던 개발자스러운 절차가 대부분 사라졌다.
2. **3단계 모델의 도착점이 연결에 달려 있다** — ADR-0001의 3단계(에이전트 활용)에서 실제로 무엇을 할 수 있는지는 그 에이전트에 무엇이 연결됐는지가 좌우한다. 연결을 다루지 않으면 3단계가 로컬 파일 범위에서 멈춘다.
3. **실무 적용 경로가 거기 있다** — 임직원의 업무 문서·이슈는 Confluence·Jira·GitHub에 있다. 연결은 교육 목표("실제 반복해서 쓸 수 있는 결과물")로 가는 경로다.

한편 1부는 온보딩 필수 분량이라 늘릴 수 없다. 범위를 넓히되 1부를 무겁게 하지 않는 방법이 필요했다.

---

## 결정 (Decision)

### 1. 2부를 신설하고, 1부의 범위 선언은 유지한다

ADR-0001을 대체하지 않고 **확장**한다. 1부는 Claude 단독으로 기본기를 잡는 자리로 그대로 두고, 2부가 **그 에이전트의 손이 닿는 범위를 넓히는** 새 범위를 추가한다.

2부는 **4단계가 아니다.** 3단계 모델이 세로축(활용 수준)이라면 연결은 가로축(닿는 범위)이다. 축이 다르므로 단계 표에 행을 더하지 않는다.

### 2. 같은 repo·같은 사이트, nav에서 부를 구분한다

| nav 위치 | 내용 |
|---|---|
| 홈 | `index.md` — 부 공통 |
| **1부 — AI 활용 기본** | `basics.md` · `intro.md` · `labs.md` |
| **2부 — 도구·데이터 연결** | `connect/index.md` · `connect/connectors.md` · `connect/mcp-servers.md` |
| 보안 및 개인정보 가이드 / 교육 운영 가이드 | 부 공통이므로 최상위 유지 |

부 이름은 **난이도가 아니라 내용**을 말한다("심화" 같은 난이도 표기를 쓰지 않는다). 2부만 이름을 갖고 1부는 무명으로 남는 비대칭을 피하려고 1부 섹션도 함께 명명한다.

### 3. 범위 경계 — "이용"까지, "개발"은 범위 밖

- **다룬다**: 커넥터 연결·해제, 승인 화면에서 확인할 것, MCP 서버 등록·선택, 잘 안 될 때 확인할 것.
- **다루지 않는다**: MCP 서버 개발·구현(ADR-0005의 비개발자 경계 유지, 개발자용 문서 포인터만 남긴다), RAG 내부 구조·구현 패턴(기존 범위 밖 선언 유지).

### 4. 연결 보안 서술의 SSoT는 `security-guide.md`

외부 연결은 데이터가 오가는 경로를 새로 만든다. 이 위험은 2부 고유가 아니라 조직 전체 보안 정책의 일부이므로, **정책 본문은 `docs/security-guide.md`에 "외부 연결" 절을 신설해 둔다.** 2부 각 페이지에는 그 자리에서 필요한 짧은 주의만 두고 상세는 링크로 넘긴다. 보안 서술이 두 곳으로 갈라져 따로 늙는 것을 막기 위함이다.

### 5. 도구 축은 이 ADR의 결정 대상이 아니다

이 ADR은 **범위 축**만 확장한다. ADR-0001의 도구 범위(Claude 단독)는 **그대로 유효**하며, ChatGPT 등으로의 도구 다원화는 이 ADR이 결정하지 않고 후속 결정에 위임한다.

그에 따라 2부 본문은 개념·보안·서버를 고르는 기준을 특정 도구 이름에 묶이지 않게 쓰고, 화면 절차만 Claude 기준으로 쓴다. 다만 **도구별 탭·분기 구조를 미리 만들지는 않는다** — 도구가 하나뿐인 시점에 빈 칸을 보여주는 손해가 더 크다.

### 6. 1부 수정은 접합부 최소

- `docs/basics.md`의 "범위 밖" 선언을 2부 포워드 링크로 바꾼다. 단 **MCP·RAG가 무엇인지 정의하는 문장은 `basics.md`에 그대로 둔다** — 용어를 정의하는 자리는 1부이고, 2부는 그 정의를 링크로 재사용한다.
- `docs/intro.md`의 MCP 관련 서술을 2부와 정합하게 점검한다.
- RAG는 여전히 범위 밖이므로 그 선언은 남긴다.

## 고려한 대안 (Alternatives considered)

### 대안 A. 별도 repo·사이트로 분리

심화 자료를 독립 사이트로 낸다. **기각:** 용어 정의·테마·CI·컨플루언스 동기화를 통째로 다시 만들어야 하고, 무엇보다 1부 용어를 링크로 재사용할 수 없어 정의가 중복된다. 정의가 두 벌이 되면 따로 늙는다.

### 대안 B. 1부 본문에 통합

`basics.md`·`intro.md`를 늘려 연결까지 담는다. **기각:** ADR-0001의 범위 선언과 정면 충돌하고, 온보딩 필수 분량이 늘어 "짧게 정리한다"는 1부 전제가 깨진다.

### 대안 C. "범위 밖" 선언 유지

지금대로 둔다. **기각:** 선언의 근거였던 진입 장벽이 커넥터 등장으로 사실상 사라졌다. 근거가 사라진 선언을 관성으로 유지하면 3단계 도착점이 로컬에 갇힌다.

### 대안 D. 도구 다원화(ChatGPT 등)를 함께 결정

범위와 도구를 한 번에 넓힌다. **기각:** 축이 다르고 파급 범위가 다르다. 도구 축은 ADR-0001의 핵심 결정을 뒤집는 일이라 1부 3단계 모델·준비물·`labs/`·`slides/` 전반을 흔든다. 순서상 범위 축을 먼저 닫고 도구 축은 별도 결정으로 다룬다.

## 결과 (Consequences)

### 긍정적 영향

- 3단계 모델의 도착점에서 실무 적용으로 이어지는 경로가 생긴다.
- 1부 온보딩 분량이 보존된다 — 필요한 사람만 2부로 간다.
- 용어 정의·테마·CI·발행 파이프라인을 그대로 재사용한다.
- 부 구분 기준이 "도구"가 아니라 "범위"라, 나중에 도구가 늘어도 nav 골격이 흔들리지 않는다.

### 부정적 영향·리스크

- **외부 제품 UI 변경에 취약하다** — 커넥터·MCP 등록 화면은 1부 내용보다 빨리 낡는다. *완화:* 화면 캡처 의존을 줄이고 개념·확인할 것 중심으로 서술하며, 공식 문서(한국어 경로) 링크를 함께 둔다.
- **연결 확대는 데이터가 나가는 경로의 확대다.** *완화:* 결정 4의 보안 절.
- **표면 간 일시적 비대칭** — docs에만 2부가 있고 `slides/`·`labs/`에는 없는 상태가 생긴다. ADR-0002가 docs SSoT → slides 후행 파생 구조이므로 구조상 허용되지만, 그 기간에 발표 자료와 사이트 구성이 어긋난다. *완화:* 후속 이슈로 파생.
- **2부 분량이 커지면 1부/2부 경계 논쟁이 재발할 수 있다.** *완화:* 결정 3의 "이용까지만" 선을 기준으로 판단한다.

### 후속 조치

- 2부 발표 슬라이드 파생(ADR-0002 구조) — **후속 이슈**
- 2부 실습 신설(ADR-0006 명명 규칙) — **후속 이슈**
- 도구 축 확장 검토 — **별도 ADR**. ChatGPT(챗봇·커넥터 축)와 Codex(개발자 코딩 에이전트 축)는 성격이 달라 분리 검토하며, 특히 Codex는 ADR-0005·ADR-0001의 비개발자 경계 판단이 선행한다.
