# ADR-0008: 결정성/비결정성 메커니즘의 명시적 가시화 — 비교표 형태로 도입

- **상태**: Accepted
- **결정일**: 2026-05-19
- **연관 이슈**: [Issue #40](https://github.com/scroogy-dev/ai-onboarding/issues/40)
- **영향 범위**: `docs/basics.md` 첫 H2 "AI 활용의 세 형태", `docs/index.md` 결정 룰 박스 직후 링크, `slides/slides.md` "AI 활용의 세 형태" 슬라이드
- **연관 ADR**: [ADR-0005](adr-0005-core-message-non-developers-make-software.md) (§3 운용 변경의 짝), [ADR-0001](adr-0001-practice-tool-scope-and-stage-model.md) (3단계 모델과 다른 차원의 분류)

---

## 배경 (Context)

ADR-0005 §3는 결정성/비결정성 메커니즘을 **결과형으로 우회 전달**한다는 원칙을 둔다. "동일 품질로 반복 보장" / "매번 결과가 조금씩 다름" 같은 결과 표현으로 학습자 경험에 메시지를 얹되, "비결정"이라는 단어 자체는 본문에서 회피한다. 이는 비개발자에게 LLM의 확률적 생성·결정적 알고리즘 차이를 90분 안에 이해시키는 비용이 크다는 판단에서 도입된 원칙이다.

본 교육 운용 시점에서 다음 두 가지가 관찰됐다.

1. **3종 비교 요구의 등장** — 사용자가 "1회성 프롬프트 vs 에이전트 스킬 vs 애플리케이션을 비교하여, 각각 결정적인지 비결정적인지, 그리고 여러 기준에서 어떤 장단점이 있고 언제 써야 하는지에 대한 간단한 비교표를 만든다"는 명시적 요구를 도입(Issue #40). 결과형 표현만으로는 이 비교표가 성립하지 않는다 — "결정성"이라는 축이 빠지면 사용자가 명시한 비교 기준 자체가 결여된다.
2. **잘못된 추론 위험** — 학습자가 에이전트 스킬을 "코드로 만드는 거니까 결정적이지 않나?"라고 추론할 가능성. 메커니즘을 한 곳에서 명시적으로 짚지 않으면 누적되어 본 교육이 가르치는 결과물의 본질을 호도할 수 있다.

ADR-0005 §3의 원칙은 본문 흐름에서 메커니즘 단어를 회피해 인지 부하를 낮춘 효용이 여전히 유효하다. 따라서 §3를 폐기하지 않고 **운용 범위를 좁히는 방향**이 적합하다.

---

## 결정 (Decision)

### 1. 결정성/비결정성 메커니즘을 비교표 1곳에서 명시적으로 가시화한다

본문(결정 룰 박스, N-2 사다리, 핵심 박스 등)은 ADR-0005 §3에 따라 **결과형 표현 유지**. 메커니즘 단어 명시는 다음 **1곳에 한정**한다.

- `docs/basics.md` 첫 H2 "AI 활용의 세 형태 — 1회성 프롬프트 · 에이전트 스킬 · 애플리케이션"
- 슬라이드 측은 위 H2와 1:1 매핑되는 단일 슬라이드 1장

이 1곳에는 다음 두 자리에서 메커니즘 단어가 등장한다.

- **단정 박스**: "생성형 AI는 기본적으로 비결정적입니다"
- **비교표 "결정성" 행**: 비결정 / 비결정 *(내부 LLM)* / 결정

### 2. 비교 라벨 3종은 결과물 형태 차원의 분류

`1회성 프롬프트` / `에이전트 스킬` / `애플리케이션`. 이 분류는 **결과물의 형태·체계화 수준**을 가른다. ADR-0001의 3단계 모델(`챗봇 사용` → `프롬프트 재활용` → `에이전트 활용`)은 **학습자의 활용 수준 사다리**로, 본 ADR의 3종 분류와 **차원이 다르다**.

| 분류 | 차원 | 본 교육에서의 자리 |
|------|------|------------------|
| ADR-0001 3단계 | 학습자 활용 수준 (사다리) | `docs/index.md` What 섹션 |
| 본 ADR 3종 | 결과물의 형태·체계화 수준 (비교) | `docs/basics.md` 첫 H2 |

두 분류는 서로 대체하지 않으며, 같은 학습자가 두 좌표축으로 자신을 인지하게 한다. `애플리케이션`은 ADR-0001 3단계 바깥에 위치하는 **비교 기준** — 학습자가 "내가 만드는 에이전트 스킬은 결정성·비용 두 축 위에서 어디에 있는가"를 두 끝점 사이에서 인지하게 하는 장치다.

### 3. 비교축 5개 — 결과형 표현이 메커니즘 단어를 받쳐주는 구조

비교축은 다음 5개로 고정한다 (Issue #40 Task 2 설계). 5축 중 **"결정성" 1축만** 메커니즘 단어를 노출하고, 나머지 4축은 결과형·자연어로 작성하여 메커니즘 단어가 본문 결과형 메시지와 정합되게 한다.

| 축 | 표현 성격 |
|----|---------|
| 무엇 | 정의 (결과형) |
| 결정성 | 메커니즘 단어 (이 자리에 한해 명시) |
| 결과 일관성 | 결과형 |
| 만드는 비용·누가 | 결과형 |
| 언제 적합한가 | 의사결정 가이드 |

### 4. ADR-0005 §3 운용 변경 — 짝으로 갱신

ADR-0005 §3에 본 ADR을 가리키는 **변경 이력(Revisions) 노트를 추가**한다. §3 원칙은 본문 기본 운용으로 유지하되, 본 ADR이 정의한 비교표 1곳에서는 메커니즘 단어를 명시적으로 가시화하는 운용 변경임을 명시한다. 두 ADR이 짝으로 운용된다.

## 고려한 대안 (Alternatives considered)

### 대안 A. 결과형으로만 비교표 구성

- **장점**: ADR-0005 §3 원칙을 100% 유지.
- **단점**: Issue #40 본문이 명시적으로 요구한 "결정 vs 비결정 차이를 알려준다", "비결정적이라는 점을 인지시킨다"와 직접 충돌. 사용자 결정과 맞지 않음.
- **기각 사유**: 사용자 요구가 메커니즘 단어의 명시적 도입을 명령하므로, 단어 회피로 응답할 수 없다.

### 대안 B. ADR-0005 §3 자체를 폐기·대체

- **장점**: 두 ADR의 짝 운용 복잡도 회피. 본문 곳곳에서 메커니즘 단어를 자유롭게 쓸 수 있음.
- **단점**: §3가 막아낸 인지 부하 효용(본문 결과형 톤 유지)이 사라짐. 결정 룰 박스·N-2 사다리·핵심 박스 같은 본문 자산이 메커니즘 단어로 어수선해질 위험.
- **기각 사유**: §3의 효용은 본문 흐름에서 여전히 유효. 폐기보다 **운용 범위 좁히기**가 비용 대비 효과 우위.

### 대안 C. 본문 곳곳에 메커니즘 단어 산포

- **장점**: 학습자가 메커니즘을 여러 자리에서 만남 → 인지 강도 ↑.
- **단점**: 인지 부하 누적. ADR-0005 §3가 막아낸 비용이 다시 발생. 본문 톤이 일관되지 않음.
- **기각 사유**: 1곳에 정점으로 박는 것이 산포보다 인지 효율이 높다. 학습자는 본문 흐름은 결과형으로 자연 흡수하고, 메커니즘 단어는 비교표 1곳에서 한 번 받으면 충분.

### 대안 D. 비교 라벨 3종을 ADR-0001 3단계와 동일화

- **장점**: 학습자가 한 좌표축만 외우면 됨.
- **단점**: "애플리케이션"은 3단계 바깥의 비교 기준이라 강제 매핑 시 의미가 호도됨. "에이전트 스킬"은 ADR-0001의 2단계와 3단계에 걸쳐 있어 1:1 매핑이 깨짐.
- **기각 사유**: 두 분류는 차원이 달라 강제 통합하면 두 자산 모두 약해진다. 별 차원으로 분리하여 두 좌표축으로 학습자를 인지시키는 것이 더 정직.
