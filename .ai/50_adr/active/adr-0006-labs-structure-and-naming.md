# ADR-0006: 실습 자료 구조 — `labs/` SSoT, 중첩 명명 규칙, stage 3 자산 패턴

- **상태**: Accepted
- **결정일**: 2026-05-09
- **연관 이슈**: [Issue #30](https://github.com/scroogy-dev/2026-ai-edu/issues/30)
- **영향 범위**: 루트 `labs/`, `docs/labs.md`, `mkdocs.yml`, `slides/slides.md`, 후속 실습 본문 작성·자산 추가 시

---

## 배경 (Context)

ADR-0001이 도입한 AI 활용 3단계 모델(챗봇 → 프롬프트 재활용 → 에이전트)은 본 교육의 학습 사다리를 정의했지만, 실제 hands-on 실습 자료의 **위치·명명·자산 구조**는 결정된 바 없었다. 이슈 #30은 실습 시리즈를 처음 만들면서 다음을 정해야 했다:

1. **위치** — 실습 자료(가이드 + Skill·템플릿·예시 자산)가 `docs/`(사이트 SSoT) 안에 있을지, 별도 디렉토리에 있을지.
2. **명명 규칙** — 한 시리즈 안에서 여러 주제와 단계가 어떻게 식별되는지(평면 vs 중첩, step 번호의 의미, stage 번호와 ADR-0001 단계 모델의 매핑).
3. **stage 3 자산 패턴** — 학습자가 받아 그대로 쓸 수 있는 템플릿·예시 HTML이 어떤 모양으로 동봉되는지.
4. **진행 원칙** — 학습자가 자료를 어떻게 따라가야 하는지(프롬프트 vs 직접 편집).
5. **범위 변경** — 본 이슈는 처음에 "디렉토리 골격만, 본문은 후속 이슈"로 잡혔으나 진행 중 step 본문까지 본 이슈에서 작성하도록 확장됨.

또한 ADR-0001은 후속 이슈로 명시된 두 항목("AI 오답노트", "자동 출제기")이 있었는데, 이슈 #30에서 step03(voca-quiz)·step04(wrong-answer-note)로 흡수되었다. 이 흡수 사실을 ADR-0001의 후속 조치 목록과 정합화할 필요가 있다.

---

## 결정 (Decision)

### 1. 위치: 루트 `labs/` SSoT, 사이트 미노출

- 실습 자료 본문(README)과 코드 자산(SKILL.md·템플릿·예시 HTML·sample-files 등)은 **repo 루트 `labs/`** 디렉토리에 둔다. 본문이 SSoT.
- 사이트(`docs/`)에는 `docs/labs.md` **단일 인덱스 페이지**만 둔다. 본문 narrative는 사이트에 노출되지 않는다.
- `mkdocs.yml` nav에 "실습" 라벨로 `labs.md`를 등록한다(top-level, 도입·보안과 동급 형제).
- **이유**: zip 단일 다운로드 친화 — 학습자는 `main.zip`을 받아 `labs/`만 열면 된다(MkDocs 빌드·플러그인 의존성 없음).

### 2. 중첩 명명 규칙: `labs/step<NN>-<topic>/stage<N>-<topic>-<설명>/`

- **step 번호** = 학습 순서(시리즈 내 등장 순서).
- **stage 번호** = ADR-0001 3단계 모델의 단계 매핑.
- 한 주제(step) 안에서 stage 1→2→3 진행으로 학습자가 단계 모델을 동일 콘텐츠로 직접 체감.
- step·stage 디렉토리는 영문 소문자·하이픈만 사용. AI-CONTEXT.md의 `docs/` 하위 규칙을 동일하게 적용해 정합 유지.

### 3. 각 step의 stage 구성은 학습 목표에 맞춰 선택

모든 step이 풀 코스(stage 1·2·3)일 필요 없다. 본 시리즈 4개 step 매핑:

| step | stage | 학습 목표 |
|------|------|----------|
| step01-weather | 1·2·3 | 자유응답 → 정형 → 파일 산출물 풀 코스(입문) |
| step02-file-classifier | 1·2 | Skill 옵션(파라미터) 설계 |
| step03-voca-quiz | 1·2 | 사진 입력·출처 충실성·외부 도구 연결 |
| step04-wrong-answer-note | 1·2·3 | 다단계 파이프라인·검수 자리·데이터/뷰 분리(종합) |

### 4. stage 1 해석: 참가 전제의 입체화

- ADR-0001은 "stage 1은 참가 전제(이미 경험)"로 정의한다.
- lab의 `stage1-` 디렉토리는 그 경험을 본 lab 맥락에서 **입체화**하는 reference 자리(예시 prompt·자유응답 캡처·관찰 포인트)로 해석한다 — ADR-0001과 충돌 없음.
- step02 stage 1처럼 매체가 Cowork·Code 필요한 경우, **단계 라벨은 학습 초점**(즉석 지시 vs Skill 정형화) 기준이며 실행 매체는 별 축임을 README에서 명시한다.

### 5. stage 3 자산 패턴: 슬롯 템플릿 + 채워진 예시 + 데이터/뷰 분리

- stage 3에서 산출되는 파일 자산은 **두 벌로 동봉**한다:
  - **슬롯 템플릿** (`*-template.html`) — Skill 디렉토리 안. 슬롯 마커(`{{...}}`)와 가변 항목 처리용 블록 반복 마커(`<!-- BLOCK:START/END -->`).
  - **채워진 예시** (`example-output.html`·`classical.html` 등) — stage 디렉토리 루트.
- step04는 step01의 고정 슬롯 패턴을 **블록 반복 마커**(가변 문항 수)로 확장한다.
- **데이터/뷰 분리**: 본 패턴의 데이터/뷰 분리는 [ADR-0007](adr-0007-data-view-separation.md)을 stage 3 자산에 적용한 사례다. 데이터는 한 곳에서 단일 출처로 관리하고, 마크다운(평문 뷰)·HTML(인쇄 뷰) 등 모든 표현은 같은 데이터에서 갈라지는 평행 형제 뷰로 본다. step04의 검수 엑셀 → 마크다운/HTML 평행 분기가 가시 사례.

### 6. 진행 원칙: ① 프롬프트로만 진행 + ② 결과물 검토·이해 의무

본 시리즈에는 짝을 이루는 두 진행 원칙이 있다.

**① 프롬프트로만 진행**

- 학습자는 모든 실습을 **프롬프트만으로** 진행한다 — 파일·코드·템플릿을 에디터로 직접 고치지 않고 AI에게 프롬프트로 요청한다.
- 이유: AI에게 "말로 소프트웨어를 움직이는" 근육을 만드는 것이 본 시리즈의 목적.
- 막혔을 때도 해결을 프롬프트로 요청한다 — 손으로 고치고 싶은 조바심이 곧 수련 지점.

**② 결과물 검토·이해 의무**

- AI가 만든 결과물(마크다운·HTML·엑셀·SKILL 지시문 등)은 **본인이 직접 읽고 이해한 상태**에서 사용·수정한다. 읽지 않은 결과물은 사용하지 않는다.
- 이해가 부족하면 AI에게 "왜 이렇게 만들었는지·이 부분이 무슨 의미인지" 다시 물어 짚어 본다.
- ①번이 검토를 면제해 주지 않는다 — 손으로 쓰지 않는 만큼 이해의 깊이는 더 의식적으로 챙긴다. 단, **검토의 깊이는 결과물의 영향 범위에 비례한다** — 한 번 쓰고 버리는 산출물은 가볍게, 반복하거나 공유할 산출물은 깊이 있게.

본 두 원칙은 짝이며, 시리즈 차원에서 함께 적용된다. `labs/README.md`·`docs/labs.md`·`docs/index.md` 도입 섹션(메타 원칙 ③ `#meta-principles`)·`slides/slides.md`(실습 섹션·메타 원칙 ③ 슬라이드) 표면에 명시한다.

### 7. 본 이슈에서 step별 가이드 본문까지 작성한 범위 변경

- 이슈 #30 1차 범위는 "디렉토리 골격만 본 이슈, 본문은 후속 이슈"였다.
- 진행 중 사용자 결정으로 본 이슈가 step01~04 본문 모두를 흡수했다.
- **이유**: step 분할은 시나리오·자산 측면에서는 독립적이지만 **공통 구조 결정**(슬롯 템플릿 + 예시 + 블록 반복 + 데이터/뷰 분리)이 4개 step에 걸쳐 일관되게 적용되어야 하므로 한 이슈에서 결정·실행·검증하는 편이 결정 일관성에 유리.

### 8. ADR-0001 후속 항목(오답노트·자동 출제기) 흡수

ADR-0001 "후속 조치" 두 항목("Gems 기반 실습의 Agent Skills · Projects 재설계")은 본 이슈에서 다음으로 흡수되었다:

- **자동 출제기** → step03-voca-quiz (사진 입력 + 옵션 + 단어별 사전 직접 링크).
- **AI 오답노트** → step04-wrong-answer-note (사진 인식 → 검수 엑셀 → 자녀용 마크다운 + 인쇄용 HTML 파이프라인).

단순 "Gems → Skill 1:1 이전"이 아니라 사용자 운영 자산(3-Gem 흐름) + 디자인 prompt까지 흡수해 시리즈의 종합 step으로 확장됨.

## 고려한 대안 (Alternatives considered)

### 대안 A. `docs/` 안에 통합 (사이트 SSoT 그대로 적용)

- **장점**: 사이트 방문자가 zip 받지 않고 본문을 즉시 읽음. 검색·nav 통합.
- **단점**: README의 상대 경로 자산 참조(`SKILL.md`·`*-template.html`·`example-output.html` 등)가 사이트 빌드 시 깨지거나 두 벌 관리 필요. zip 단일 다운로드 시 사이트 빌드 산출물(`site/`)을 따로 받아야 하는 부조리.
- **기각 사유**: 학습자가 자료를 받아 로컬에서 따라가는 것이 본 시리즈 진행 방식인데, "사이트 안에 본문"은 이 진행과 정합하지 않음. (단, 사이트 노출 자체의 가치는 별도 후속 이슈로 보류했고, Issue #36에서 (a) 현행 유지로 종결.)

### 대안 B. 평면 명명 (`labs/01-weather-prompt/`, `labs/02-weather-skill/` 등)

- **장점**: 디렉토리 깊이가 얕음. 학습 순서가 번호로 직관적.
- **단점**: 한 주제(step)와 단계(stage)가 디렉토리 이름에 섞여 학습자가 "지금 이게 어떤 step의 어떤 stage인지" 추적하기 어려움. step 내부의 stage 1·2·3 흐름이 평면 나열 속에 묻힘.
- **기각 사유**: ADR-0001 3단계 모델을 학습자가 동일 콘텐츠 안에서 직접 체감하려면 step·stage 두 축이 디렉토리에서 명시 분리되어야 함.

### 대안 C. step 본문은 후속 이슈로 분할 (1차 범위 유지)

- **장점**: 이슈 단위가 작아 머지 가능 시점이 빠름.
- **단점**: stage 3 자산 패턴·데이터/뷰 분리 같은 **공통 구조 결정**이 4개 step에 걸쳐 일관되게 적용되려면 한 이슈에서 결정·실행·검증되는 것이 안전. 후속 이슈로 분리하면 step별로 패턴이 흔들릴 위험.
- **기각 사유**: 본 시리즈가 처음 만들어지는 시점이라 패턴 자체를 결정·정착시키는 비용이 핵심이고, 그 비용을 한 이슈에 집중시키는 편이 결정 일관성에 유리.

### 대안 D. stage 3 자산 패턴: 매번 prompt로 새로 생성 (동봉 없음)

- **장점**: "프롬프트로만 진행" 원칙과 가장 강하게 정합. 학습자가 매번 디자인까지 만들어보는 경험.
- **단점**: 학습자가 템플릿 구조·슬롯 매핑까지 매번 프롬프트로 재생성해야 함. 인쇄 친화 CSS·블록 반복 마커 같은 **재현 비용이 큰 디테일**이 매번 풀이 대상이 되어 학습 초점이 흐려짐.
- **기각 사유**: 디자인 자산 자체가 사용자의 디자인 prompt 결과물(즉, "프롬프트로만 진행"의 산출물)이므로 동봉해도 원칙 위배 아님. 학습자는 동일 패턴으로 새 톤(`minimal.html`·`modern.html` 등)을 형제 자산으로 추가 가능.

## 결과 (Consequences)

### 긍정적 영향

- **zip 친화 + 로컬 따라가기**: 학습자가 자료를 받아 로컬에서 그대로 진행. 사이트 빌드·플러그인 의존성 없음.
- **단계 모델 가시화**: step·stage 두 축 명시로 학습자가 ADR-0001 단계 모델을 동일 주제 안에서 직접 체감.
- **자산 패턴 재사용**: 슬롯 템플릿 + 채워진 예시 + 블록 반복 + 데이터/뷰 분리는 후속 step·다른 시리즈에도 재사용 가능한 골격.
- **진행 원칙의 일관성**: "프롬프트로만 진행"이 시리즈 차원의 메시지로 박혀 추후 자료 추가 시 결정 기준 제공.
- **ADR-0001 후속 정리**: 후속 항목 두 가지(오답노트·자동 출제기)가 본 이슈에서 흡수·해소됨.

### 부정적 영향·리스크

- **사이트 방문자 동선의 분리**: 사이트에서 진입한 학습자는 zip을 받거나 GitHub로 이동해야 본문을 읽을 수 있음. 즉시 읽기 동선이 한 단계 길어짐.
  - *완화*: `docs/labs.md` 인덱스에서 GitHub `labs/` 링크와 zip 링크를 명확히 안내. 학습자 피드백 후 본문의 docs 통합 여부를 후속 이슈로 재검토 (Issue #36에서 (a) 현행 유지로 종결).
- **자산 두 벌(템플릿 + 예시) 관리 비용**: stage 3 자산이 슬롯 템플릿과 채워진 예시 두 파일로 동봉되어 한쪽만 갱신 시 정합 깨질 위험.
  - *완화*: SKILL.md의 슬롯 매핑 표가 두 자산 사이의 정합 기준점. 갱신 시 SKILL.md를 같이 본다.
- **step 본문이 한 이슈에 누적되어 PR 규모 확대**: 이슈 #30이 결국 4개 step 본문 + slides + ADR을 포함하는 큰 이슈가 됨.
  - *완화*: 이슈 #30은 본 ADR로 결정 일관성을 못박는 정착 이슈로 자리매김. 후속 step·시리즈는 본 ADR을 기준 삼아 작은 이슈 단위로 분할 가능.

### 후속 조치

- [ADR-0001](adr-0001-practice-tool-scope-and-stage-model.md) 변경 이력에 2026-05-09 항목 추가 — "Gems 기반 실습 재설계" 후속 조치 두 항목이 Issue #30에서 step03·step04로 흡수 처리됨을 기록. **(완료 — 본 이슈에서 처리)**
