## 1. 계획과 실행의 분리

> **상태**: 이슈 #32 반영 완료 (2026-05-09). docs 도입 메타 원칙 ① 박스(`#meta-principles`)·slides 메타 원칙 ① 슬라이드 동기화. ADR 미신설(메시지 무게에 비해 ADR-0001 stage 모델과 결이 달라 보완 자리 어색).

- **요지**: AI에게 한 번에 "계획 + 실행"을 시키지 말고, 먼저 계획만 받고 검토한 뒤 실행시키는 흐름이 효과적인가? 어떤 상황에서 가치가 큰가?
- **교육적 함의**: 비개발자가 큰 작업을 AI에 맡길 때 결과 품질·통제권 확보 패턴.
- **연결 지점**: ADR-0001의 3단계 모델(stage 2 Skill 설계 vs stage 3 실행)과도 닿음. 별도 교육 주제가 될 수도 있음.

## 2. 페르소나는 효과적인가?

> **상태**: 이슈 #32 반영 완료 (2026-05-09). docs 메타 원칙 ⑤ 박스(`!!! note` 톤 분리·"본 강의의 현재 입장")·slides ⑤ 슬라이드(emerald 권장 / amber 보수 두 카드) 정착. 입장은 **조건부 권장** — 톤·형식 지정 권장, 전문성 부여 보수적. 대규모 검증 실험은 본 이슈 비포함(추후 검증 시 별 이슈).

- **요지**: "너는 ~ 전문가야"식 페르소나 부여가 실제로 결과 품질에 영향을 주는가? 청중에게 권장할 가치가 있나?
- **교육적 함의**: 항간에 널리 퍼진 prompting 팁의 실효성 검증. 비개발자 청중에게 "권장 vs 비권장" 입장을 정해야 함.
- **방향**: 검증·실험 성격이 강함. 결과에 따라 교육 자료에서 다루는 톤이 달라짐(권장/비권장/조건부).

## 3. 데이터와 뷰의 분리

> **상태**: 이슈 #32 반영 완료 (2026-05-09). docs 메타 원칙 ② 박스·slides ② 슬라이드 정착. **ADR-0007 신설** — ADR-0006 결정 5(stage 3 자산 패턴) 부속 메시지를 시리즈 차원 사고 원칙으로 격상.

- **요지**: AI가 만드는 산출물에서 "내용(데이터)"과 "표현(뷰)"을 분리하는 사고. step01-weather로 비유하면 날씨 **값**(온도·체감·우산)과 그것을 보여주는 **HTML 리포트 템플릿**을 분리.
- **교육적 함의**: 비개발자에게도 적용 가능한 구조적 사고 — 한 번 잘 만든 템플릿을 여러 데이터에 재사용. step01-weather stage 3 흐름(템플릿 읽기 → 슬롯 치환)이 자연스러운 진입점.
- **방향**: 새로운 step 후보 또는 기존 step 본문 보강 후보. ADR로 "교육 원칙"에 추가될 수도 있음.

## 4. 컨텍스트는 어느 정도로 유지해야 하는가? 언제 새 대화를 여는 것이 좋은가?

> **상태**: 이슈 #32 반영 완료 (2026-05-09). docs 메타 원칙 ④ 박스(컨텍스트 정의·새 대화 신호·표면별 명령·컨텍스트 크기 참고)·slides ④ 슬라이드 정착. 표면별 명령(Claude.ai 챗봇·Cowork 새 대화 / Claude Code `/clear`) + 컨텍스트 크기(200K·Enterprise 일부 500K·Code 일부 1M `/model`) + 외부 docs 한국어 링크 2개 포함.

- **요지**: 한 대화방에 작업을 계속 누적할 것인가, 일정 시점에 새 대화를 열 것인가? 판단 기준은?
- **교육적 함의**: 비개발자가 자주 부딪히는 실무 질문. "대화방 관리"에 대한 가이드라인이 필요.
- **방향**: 가이드/이론 페이지 후보. 기준(주제 변경·맥락 오염·길이 임계 등)을 정리해야 함.

## 5. 외부 컨텍스트와 MCP — 개념 인지 수준 (설치·등록 how-to는 범위 밖)

> **상태**: 이슈 #34 반영 완료 (2026-05-12). `docs/basics.md` "기본 용어와 범위" 페이지의 `## 외부 컨텍스트` 섹션으로 정착 — MCP·RAG 용어를 같은 우산 아래 다른 레이어로 정리하고, "Claude 단독 사용·설치/내부 구조 범위 밖" 명시. slides 동기화 1장(slate 회색조 카드).

- **본 시리즈 입장**: MCP 서버의 **설치·등록 how-to는 본 교육 범위 밖.** "MCP가 무엇이고 왜 필요한지" 정도만 가볍게 언급하는 수준 — 비개발자 청중에게 "외부 컨텍스트를 붙이는 표준 방식이 있다"는 신호만 남긴다.
- **요지**: AI에게 "외부 자료(사내 문서·웹·DB 등)"를 컨텍스트로 붙여 답하게 하는 표준 연결 방식이 MCP(Model Context Protocol). 비개발자 청중은 그 **존재와 쓰임**을 아는 수준까지만.
- **교육적 함의**:
  - "내가 가진 자료를 기반으로 답해줘"가 가능해진다는 **감각만** 전달. RAG·MCP 내부 구조·설치 방법·예시 자료원은 다루지 않는다.
  - 본 시리즈는 Claude 단독·기본 컨텍스트 구성(첨부·`/clear`·메타 원칙 ④)이 핵심이고, MCP는 "그 너머가 있다"는 신호로만 위치시킨다.
  - 후속 항목 10(바이브 ↔ 에이전틱)의 에이전틱 쪽 도구가 실제로 어떻게 생겼는지 보여주는 구체 사례로 호명 가능.
- **방향**:
  - 사이트 안내 페이지(`docs/index.md` 도입부 또는 별도 짧은 용어/범위 페이지) 짧은 섹션 — "MCP가 뭔지" 한 문단 + "본 교육 범위 밖" 명시.
  - ADR 신설 불필요. ADR-0001(Claude 단독 범위)의 경계를 부드럽게 안내하는 자리.
  - 분량 짧게 — 한 문단 + 1~2줄 범위 명시. how-to는 포함하지 않음.
- **연결 지점**:
  - ADR-0001(3단계 모델 + Claude 단독 범위) — 본 시리즈 경계의 외곽.
  - 메타 원칙 ④(컨텍스트 관리) — 외부 컨텍스트 영역의 신호.
  - 후속 항목 10(바이브 ↔ 에이전틱 차이) — 에이전틱 쪽 도구의 구체 사례.
  - 후속 항목 11(마크다운 용어 해소) — 같은 "범위 밖 안내·용어 해소" 결, 묶음 후보.

## 7. step01-weather stage 3 — Claude HTML 디자인 시연·에셋 재생산

- **요지**: 현재 `labs/step01-weather/stage3-weather-report/`는 미리 만들어둔 `example-output.html` 템플릿을 학습자가 받아 슬롯을 치환하는 흐름. 수업에서 **"Claude에게 HTML 디자인까지 맡길 수 있다"** 를 가볍게 시연하는 단계를 추가할 수 있음.
- **교육적 함의**: 비개발자에게 "디자인 자산도 AI에 위임 가능"을 보여주면서, 동시에 "한 번 잘 만든 템플릿을 재사용한다"는 데이터/뷰 분리 메시지(후속 항목 3)와도 연결.
- **방향**:
  - **수업 진행 노트**: stage 3 시작 직후 1분 분량의 시연(빈 prompt → Claude가 디자인한 HTML 받기) 끼워넣기. 이후 본문은 기존 템플릿 흐름으로 복귀.
  - **에셋 교체 가능성**: 시연 결과 디자인이 현재 `example-output.html`보다 좋으면 교체 검토. 단, 본 lab은 **템플릿이 미리 있다는 전제**로 설계되어 있어 교체 시 README 본문은 손대지 않아도 됨(이미지/슬롯 구조만 호환되면 됨).
- **연결 지점**: 후속 항목 3(데이터와 뷰의 분리)·항목 1(계획과 실행의 분리 — "디자인부터 만들기 → 데이터 채우기"의 2단계 진행).

## 8. AI 결과물에 대한 학습자 검토·이해 의무

> **상태**: 이슈 #32 반영 완료 (2026-05-09). docs 메타 원칙 ③ 박스(검토 깊이 차등화 단서 포함)·slides ③ 슬라이드·`labs/README.md` 진행 원칙 ②·`docs/labs.md` 진행 원칙 ②·**ADR-0006 결정 6** 두 원칙 보강(① 프롬프트로만 + ② 결과물 검토·이해 의무)·**메모리 `feedback_labs-review-output.md`** 신설 정착.

- **요지**: AI가 만들어낸 결과물(마크다운 본문, SKILL.md instructions, HTML, 엑셀 스키마, 코드 등)은 학습자가 **반드시 직접 읽고 이해한 상태**에서 사용·수정해야 한다. 본 시리즈의 진행 원칙(프롬프트로만 진행)과 짝을 이루는 두 번째 원칙: 손으로 안 쓰지만 **검토는 한다**.
- **교육적 함의**:
  - "프롬프트로만 진행" 원칙이 검토를 면제해 주는 게 아님을 명시 — 오히려 손으로 쓰지 않으니까 **이해의 깊이를 의식적으로 챙겨야** 한다.
  - 비개발자에게 "AI가 만든 걸 그대로 돌리는" 습관이 굳지 않도록 시리즈 차원에서 톤 잡기.
  - step04 stage 2의 검수 자리(인식 결과 엑셀)와 정합 — 검수는 step04에 한정된 패턴이 아니라 시리즈 전체의 자세.
- **방향**:
  - `labs/README.md` 진행 원칙 섹션에 두 번째 항목으로 추가 ("프롬프트로만 진행" 다음에 "결과물은 반드시 읽고 이해한다") 또는 별도 짧은 섹션.
  - `docs/labs.md`에 mirror admonition.
  - 메모리 후보 — 시리즈 차원 원칙이라 `feedback_labs-prompt-only.md`와 짝이 되는 신규 메모리(예: `feedback_labs-review-output.md`)로 저장.
- **연결 지점**: 후속 항목 1(계획과 실행의 분리 — 검토 자리를 명시적으로 두는 같은 사고)·항목 4(컨텍스트 관리). step04 stage 2가 이 원칙을 가장 직접적으로 보여주는 자리이므로 step04 본문에서도 한 줄 호출 가능.

## 9. labs README → docs 통합 (웹 읽기 경로)

- **요지**: 현재 `labs/` 하위 README는 사실상 학습 가이드 본문(stage 1·2·3 narrative, before/after 비교, 트러블슈팅 표). 그런데 `docs/labs.md`는 인덱스 한 페이지뿐이라 사이트 방문자는 zip을 받거나 GitHub로 가야만 본문을 읽을 수 있다.
- **현재 결정 근거 (이슈 #30 Task 1)**: zip 단일 다운로드 친화 + README 안의 상대 경로 자산 참조(`SKILL.md`·`*-template.html`·`example-output.html` 등)가 사이트로 옮기면 깨짐. 그래서 `labs/`는 SSoT로 격리, `docs/labs.md`는 인덱스만.
- **고민 지점**:
  - 학습자가 GitHub 페이지에서 README를 직접 읽는 것으로 충분한가, 아니면 사이트 nav에서 진입한 학습자가 본문을 못 읽고 떠나는 비용이 더 큰가?
  - 슬라이드(`slides/`)에서도 같은 문제 — labs 슬라이드는 인덱스 수준이고 본문 narrative는 README에만 존재. docs와 slides 양쪽 본문을 어떻게 채울지 정책 필요.
- **방향**:
  - **(a) 그대로 유지** — 학습자 피드백 받고 결정. GitHub 페이지 렌더링이 잘 되므로 즉시 문제는 아님.
  - **(b) per-step 요약 narrative 페이지 신설** — `docs/labs/step01-weather.md` 등에 핵심 메시지·미리보기·GitHub 링크. README 본문은 `labs/`에 그대로 두고 docs는 요약. 두 벌 관리 부담은 있으되 자산 경로 충돌 회피.
  - **(c) README를 docs로 이전, `labs/`는 코드 자산만** — 가장 깨끗한 분리지만 이슈 #30·ADR-0006 결정(labs/ SSoT) 뒤집는 큰 변경.
- **연결 지점**: 이슈 #30 Task 1 결정·ADR-0002(docs SSoT·slides 단방향)·작성 예정 ADR-0006(labs 구조).

## 10. 바이브 코딩과 에이전틱 엔지니어링의 차이 (용어 구분 + 검수 자세 연결)

> **상태**: 이슈 #34 반영 완료 (2026-05-12). `docs/basics.md` "기본 용어와 범위" 페이지의 `## 바이브 코딩과 에이전틱 엔지니어링` 섹션으로 정착 — 두 활동 정의 + 한 줄 대비 + "본 강의는 둘 사이의 가벼운 입문" + 메타 원칙 ③ 링크. slides 동기화 1장(공통 카드 1열).

- **본 시리즈 입장**: 비개발자 청중에게 **에이전틱 엔지니어링까지 요구하지 않는다.** 다만 두 활동의 **차이는 알고**, 그 차이로부터 "AI가 만든 핵심 산출물은 내가 검수한다"는 자세를 자연스럽게 따라가게 한다.
- **요지**: "바이브 코딩(vibe coding)"과 "에이전틱 엔지니어링(agentic engineering)"은 둘 다 AI로 무언가를 만들지만 활동의 성격이 다르다.
  - **바이브 코딩**: 결과물의 동작·구조를 깊이 검증하지 않고 "느낌"으로 AI에 맡겨 빠르게 만드는 활동. 학습·프로토타이핑·1회용 자동화에서 유효.
  - **에이전틱 엔지니어링**: AI 에이전트가 사람의 의도를 안정적으로 수행하도록 컨텍스트(규칙·도메인·계약·결정)와 자산(스킬·템플릿·검토 자리)을 의도적으로 설계하는 활동. 비개발자 청중에게 요구하는 영역은 아님.
- **교육적 함의**:
  - 비개발자 청중도 두 용어를 어디선가 접하므로, 첨단 용어를 일찍 해소해 잘못된 기대(다 같은 활동)·잘못된 좌절(왜 한 번에 안 되나)을 방지한다.
  - 핵심 다리는 **검수 자리**: "내가 알아야 할 핵심 산출물(보고서 본문·시험지·발표 자료 등)은 AI가 만들었더라도 내가 읽고 이해한 상태로 쓴다." — 메타 원칙 ③ "AI 결과물 검토·이해 의무"의 **왜**를 받쳐주는 용어 배경이 된다.
  - 비개발자 친화 대조: "한 번 던지고 결과 그대로 쓴다 = 바이브 / 한 번 잘 만든 컨텍스트·자산을 반복 활용 = 에이전틱". 본 시리즈는 둘 사이의 가벼운 입문(프롬프트로만 진행 + 결과물 검수)에 해당.
- **방향**:
  - 사이트 안내 페이지(`docs/index.md` 도입부 또는 별도 짧은 용어 페이지)에 용어 해소 섹션 후보. 메타 원칙·진행 원칙과는 결이 다른(용어/지형 소개) admonition.
  - ADR 신설보다는 docs 본문 보강 + 슬라이드 1장 수준. 입장은 가볍게: "둘 다 유효한 활동, 본 시리즈는 비개발자 입장에서 검수 자리만 챙기면 됨".
  - 분량 주의 — 차이를 길게 설명하기보다 "이 시리즈에서 당신에게 요구하는 만큼"을 명확히 자르는 데 무게.
- **연결 지점**:
  - 메타 원칙 ③(결과물 검토·이해 의무) — 본 항목의 핵심 다리.
  - 메타 원칙 ①(계획·실행 분리) — "검수 자리를 명시적으로 두는" 사고의 짝.
  - ADR-0006(labs 진행 원칙 ① 프롬프트로만 + ② 결과물 검수) — 시리즈 차원에서 이미 같은 자세로 설계되어 있음을 뒷받침.
  - 후속 항목 5(MCP·외부 컨텍스트) — 에이전틱 쪽 도구의 구체 사례. 본 항목에서는 "그건 별도 영역"으로만 가볍게 호명.

## 11. 마크다운이 무엇인지 — 기본 용어 해소

> **상태**: 이슈 #34 반영 완료 (2026-05-12). `docs/basics.md` "기본 용어와 범위" 페이지의 `## 마크다운` 섹션으로 정착 — 한 문단 정의 + 한 줄 예시 + "문법 학습 안 함" 명시. 본문 첫 등장 자리 링크 보완 2곳(`docs/index.md` 메타 원칙 ② 뷰 예시 / `docs/labs.md` 진행 원칙 ② 결과물 검토). slides 동기화 1장(공통 카드 1열).

- **요지**: docs/slides 본문에서 "마크다운"은 사전 설명 없이 등장한다("뷰 = 마크다운·HTML·슬라이드 등", "산출물 = 마크다운·HTML·엑셀" 등). 비개발자 청중에게는 사이트 진입 단계에서 막히는 첫 용어가 될 수 있다.
- **교육적 함의**:
  - 마크다운이 뭔지 모르면 메타 원칙 ②(데이터/뷰 분리)·labs 진행 원칙·`step04` 산출물 흐름이 모두 흐릿해진다 — "왜 이게 산출물 포맷의 하나로 묶이는지"가 안 잡힌다.
  - 본 시리즈 청중은 어쨌든 마크다운으로 작성된 문서·리포트(`step04` 자녀용 학습 리포트 등)를 다루게 되므로 어디선가 한 번은 짧게 해소해야 한다.
  - 강의 톤: "텍스트만으로 서식(제목·목록·강조·표)을 표현하는 가벼운 문서 형식, `.md` 확장자, AI가 가장 잘 다루는 출력 포맷 중 하나" 수준. **문법 학습은 아님** — 비개발자에게 마크다운 문법을 가르치는 자리가 아니라, 단어가 등장했을 때 멈추지 않게 해소하는 자리.
- **방향**:
  - 사이트 안내 페이지(`docs/index.md` 도입부) 짧은 admonition, 또는 별도 짧은 용어 페이지(예: `docs/glossary.md`).
  - 후속 항목 10(바이브 ↔ 에이전틱 차이)과 동일한 "용어 해소" 결 — 묶어서 짧은 용어 페이지 하나로 갈 가능성 있음.
  - 분량 짧게: 2~3문장 + (선택) 한 줄 예시("`# 제목` → 큰 제목, `**굵게**` → **굵게**"). 본격 문법 학습은 본 시리즈 범위 밖.
- **연결 지점**:
  - 메타 원칙 ②(데이터/뷰 분리) — "뷰"의 예시로 마크다운이 호명되는 자리.
  - 후속 항목 10(바이브 ↔ 에이전틱 차이) — 동일한 "기본 용어 해소" 결, 묶음 처리 후보.
  - `docs/labs.md`·`step04-wrong-answer-note` 본문 — 산출물 포맷으로 마크다운이 호명되는 자리.
