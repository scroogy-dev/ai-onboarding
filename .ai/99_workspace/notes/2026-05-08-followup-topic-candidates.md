# 후속 이슈 후보군 (개념 단계)

> 작성일: 2026-05-08
> 출처: 이슈 #30 작업 중 사용자가 떠올린 항목. 본 이슈 스코프가 커지는 것을 막기 위해 별도 보관.
> 상태: 개념 단계. GitHub 이슈로 승격 전, 주제 정리·범위 확정 필요.

---

## 1. 계획과 실행의 분리

- **요지**: AI에게 한 번에 "계획 + 실행"을 시키지 말고, 먼저 계획만 받고 검토한 뒤 실행시키는 흐름이 효과적인가? 어떤 상황에서 가치가 큰가?
- **교육적 함의**: 비개발자가 큰 작업을 AI에 맡길 때 결과 품질·통제권 확보 패턴.
- **연결 지점**: ADR-0001의 3단계 모델(stage 2 Skill 설계 vs stage 3 실행)과도 닿음. 별도 교육 주제가 될 수도 있음.

---

## 2. 페르소나는 효과적인가?

- **요지**: "너는 ~ 전문가야"식 페르소나 부여가 실제로 결과 품질에 영향을 주는가? 청중에게 권장할 가치가 있나?
- **교육적 함의**: 항간에 널리 퍼진 prompting 팁의 실효성 검증. 비개발자 청중에게 "권장 vs 비권장" 입장을 정해야 함.
- **방향**: 검증·실험 성격이 강함. 결과에 따라 교육 자료에서 다루는 톤이 달라짐(권장/비권장/조건부).

---

## 3. 데이터와 뷰의 분리

- **요지**: AI가 만드는 산출물에서 "내용(데이터)"과 "표현(뷰)"을 분리하는 사고. step01-weather로 비유하면 날씨 **값**(온도·체감·우산)과 그것을 보여주는 **HTML 리포트 템플릿**을 분리.
- **교육적 함의**: 비개발자에게도 적용 가능한 구조적 사고 — 한 번 잘 만든 템플릿을 여러 데이터에 재사용. step01-weather stage 3 흐름(템플릿 읽기 → 슬롯 치환)이 자연스러운 진입점.
- **방향**: 새로운 step 후보 또는 기존 step 본문 보강 후보. ADR로 "교육 원칙"에 추가될 수도 있음.

---

## 4. 컨텍스트는 어느 정도로 유지해야 하는가? 언제 새 대화를 여는 것이 좋은가?

- **요지**: 한 대화방에 작업을 계속 누적할 것인가, 일정 시점에 새 대화를 열 것인가? 판단 기준은?
- **교육적 함의**: 비개발자가 자주 부딪히는 실무 질문. "대화방 위생"에 대한 가이드라인이 필요.
- **방향**: 가이드/이론 페이지 후보. 기준(주제 변경·맥락 오염·길이 임계 등)을 정리해야 함.

---

## 5. 외부 컨텍스트(RAG)를 위한 MCP 서버

- **요지**: AI에게 "외부 자료(사내 문서·웹·DB 등)"를 컨텍스트로 붙여 답하게 하려면 어떻게 하나? Claude Desktop에서 MCP 서버를 통해 외부 자료원을 연결하는 방법.
- **교육적 함의**: 비개발자도 "내가 가진 자료를 기반으로 답해줘"가 가능해진다는 점이 핵심. RAG 개념 자체를 어렵게 다루지 않고, "이 폴더 / 이 사이트를 보고 답해줘"의 감각으로 전달.
- **범위 분리**: 비개발자 청중은 **Claude Desktop의 MCP 서버 등록**까지가 표준. **CLI(Claude Code)의 MCP 활용**은 개발자용도 — 별도 페이지/주석으로 분리하거나 본 교육 범위 밖으로 둘 가능성.
- **방향**: 새 step 또는 가이드 페이지 후보. ADR-0001의 "Claude 단독" 범위와 함께 "외부 컨텍스트 연결 = MCP" 정책으로 묶일 수 있음.

---

## 6. Claude Desktop에서 사용량·모델 정보 확인

- **요지**: Claude Desktop의 "Code" 탭을 선택하면 누적 사용량 정보(개요·모델별)를 볼 수 있다는 점을 안내 자료에 추가.
- **교육적 함의**: 비개발자도 본인 요금제 한도를 체감하고 모델 선택의 효과(추론 무거운 작업 vs 단순 지시)를 가늠할 수 있게 함. 메모리에 이미 적힌 "모델 선택은 추론 vs 지시 이행 축" 가이드와 짝.
- **방향**: 별도 step이 아니라 **사이트 안내 페이지(`docs/index.md` 또는 별도 가이드)에 짧은 섹션 추가**가 자연스러움. 스크린샷 1~2장이면 충분할 가능성. 캡처 시점의 UI에 dependent하므로 갱신 정책도 같이 결정 필요.
