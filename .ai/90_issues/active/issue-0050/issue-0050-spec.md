# Issue #50 스펙 ― 줄표 정리와 문자 통일: 1부·공통 페이지와 labs·slides

## 목표 (Goal)

발행물 전체(docs·labs·slides·mkdocs.yml)의 줄표를 국립국어원 문장부호 규정에 맞게 정리한다. 산문에 쓰인 줄표는 없애고 규정 용법인 부제 자리에만 남기며, 남기는 줄표는 한국어 줄표 문자(U+2015)로 통일한다.

**적용 기준** (2026-08-12 사용자 확정. 근거는 국립국어원 「문장 부호 해설」(2014))

**① 규정 근거**

- **제15항 줄표(―)**: "제목 다음에 표시하는 부제의 앞뒤에 쓴다." 다만 뒤에 오는 줄표는 생략할 수 있다. 이것이 줄표 항의 **유일한 본항 용법**이다.
- **제4항 쉼표 (13) [붙임 1·2]**: 문장 중간에 끼어든 어구의 **앞뒤에** 쉼표 대신 줄표를 쓸 수 있고, 끼어든 어구 안에 쉼표가 있으면 줄표를 써야 한다.
- 두 용법 모두 어구를 **감싸는** 형태다. 따라서 「라벨 ― 부연」처럼 한쪽만 여는 형태는 규정에 없는 용법이며, 영문 em dash 관행이 유입된 것이다.
- 해설은 "줄표와 붙임표는 길이로 구분한다. 줄표가 붙임표보다 상대적으로 길다"고 명시한다 ― 붙임표(-)는 열거 묶기·밀접 관련 표시용이라 부제에 쓰지 않는다.

**② 문자 (U+2014 → U+2015)**

- 남기는 줄표는 **U+2015 HORIZONTAL BAR(―)**로 통일한다. 국립국어원 해설 원문이 쓰는 문자다 (해설 PDF 89쪽 전체에서 U+2015 36회 대 U+2014 1회, 줄표 항이 실린 쪽 안에서는 U+2015만 12회이며 조항 표제도 `15 줄표(―)`).
- **U+2014 EM DASH는 발행물에서 0건**이 되어야 한다. 영문 조판 문자이며 한국어 규정 근거가 없다.
- 붙임표 U+002D(-)·엔 대시 U+2013(–)·빼기 기호 U+2212(−)는 별개 문자로 대상이 아니다. 특히 U+2212 3건은 수식의 뺄셈 기호(`5⁄6 − 1⁄4`, `(total_count − 오답수)`)로 올바른 사용이다.

**③ 줄표를 남기는 자리 (부제 용법)**

- 제목(H1~H6)·admonition 제목
- `mkdocs.yml`의 nav 라벨
- 링크 라벨. 대상 문서 제목을 그대로 반영하므로 제목을 따라간다. 부 명칭 "2부 ― 도구·데이터 연결"은 전부 링크 라벨 안에 있어 여기 해당한다

**④ 줄표를 없애는 자리 (산문)**

- 표제·라벨 뒤 짧은 부연: 쌍점(:) 또는 문장 분리
- 부연이 길어지면: 부호 대신 하위 목록·문장 분리로 구조화 (쌍점 뒤가 길어지면 앞 문맥이 희석됨)
- 쌍점이 이미 라벨 구분자로 쓰인 자리: 쌍점이 한 줄에 두 번 나오지 않도록 괄호·문장 분리로 처리
- **삽입 어구를 앞뒤로 감싼 줄표**: 규정 용법이지만 비개발자 대상 교육 문서에서는 읽기 부담이 있어 괄호·문장 분리로 바꾼다. 기준을 「줄표 = 부제」 하나로 단순화하려는 것이다
- 표 셀 안의 줄표 전부. 1열의 명칭 라벨("1단계 ― 챗봇 사용")도 포함하며, 슬라이드의 `―<br/>`는 `:<br/>`로 바꿔 줄바꿈 구조를 유지한다
- `labs/` SKILL.md 코드블록 안의 출력 형식 명세와 예시 출력. 형식 명세와 예시 출력은 같은 형태로 맞춰 실습자가 보는 결과물과 어긋나지 않게 한다

**⑤ 기호 자리 (문장부호가 아니라 규정 소관 밖 ― 문자만 U+2015로 통일)**

- 표의 "해당 없음" 기호(`| ― |`·`| ― (회사가 계약) |`)와 그 기호를 설명하는 범례 행
- HTML 자산의 `<title>`·HTML/CSS 주석·장식 기호(`― 기억 포인트`)·인용 출처(`― 담당 튜터 이서연`)·페이지 표기(`― 1 / 1 ―`)

## 기타 피드백 (번외)

줄표 정리와 무관하지만 사용자 점검 중 함께 지시받아 이 이슈에서 처리하는 항목이다. 별도 Task를 두지 않고 Task 4(docs 사용자 점검·피드백 루프)의 피드백 반영으로 처리하며, 완료의 정의에도 넣지 않는다 ― 이 이슈의 합격 조건이 아니라 곁다리 반영이기 때문이다.

- **제품 나열 순서를 Claude → ChatGPT → Gemini로 통일** (2026-08-12 사용자 지시). 기존은 Claude · Gemini · ChatGPT 순이었다. 가로 나열(산문·표 셀)뿐 아니라 표의 세로 행 순서와 회사별 짝꿍 표(Anthropic → OpenAI → Google)도 같은 순서로 맞춘다 ― 같은 세 제품을 가리키는 나열이라 한쪽만 바꾸면 페이지 안에서 순서가 갈린다.
  - 대상 9곳: `docs/intro.md` 3곳(절 제목·대표 제품 표 행 순서·회사별 표 행 순서), `docs/index.md` 2곳(참가 대상 산문·3단계 표 셀), `docs/operation-guide.md` 1곳(대상 안내 산문), `slides/slides.md` 3곳(회사별 표 행 순서·발표자 노트·3단계 표 셀).
  - `docs/operation-guide.md` 22행 사전설문 보기(`Claude, ChatGPT, Gemini, 기타`)는 이미 이 순서라 손대지 않는다.
  - `docs/intro.md` 절 제목의 앵커 `{ #products }`는 그대로 두어 이 절을 가리키는 링크(같은 파일 133행)가 깨지지 않게 한다.
  - slides는 ADR-0002상 docs 파생이라 원칙적으로 docs 확정 후 정리하지만, 이 항목은 문장 구조를 건드리지 않는 나열 순서 변경이라 docs와 같은 회차에 반영한다.

- **모델 버전 번호 현행화** (2026-08-12 사용자 지시). 문서의 예시 표기가 `Fable 5·Opus 4.8·Sonnet 4.6·Haiku 4.5`로 낡아 있었다. 최신 라인업은 **Fable 5 / Opus 5 / Sonnet 5 / Haiku 4.5**이며, Haiku만 4.5 그대로다.
  - 대상 3곳: `docs/intro.md` 101행(라인업 안내 인용문), `slides/slides.md` 729행(슬라이드 하단 주석)·743행(발표자 노트).
  - 라인업 **이름**만 나오는 자리(모델 비교 표, 절 제목, 사용량 화면 설명 등)는 버전 번호가 없어 손대지 않는다.
  - `docs/index.md`의 「참고: 컨텍스트 크기」는 claude.ai 플랜의 서비스 한도를 공식 지원 문서 링크와 함께 인용한 것이라 모델 스펙과 별개다. 버전 번호 현행화 대상은 아니며, 아래 별도 항목으로 한도 수치를 따로 최신화했다.

- **컨텍스트 크기 현행화** (2026-08-12 사용자 지시). 「참고: 컨텍스트 크기」의 수치가 낡아 있었다(모든 모델·유료 플랜 200K, Enterprise 일부 모델 500K, Claude Code 일부 모델 1M). 공식 문서 대조 결과 최신 모델(Fable 5·Opus 5·Sonnet 5)의 컨텍스트 윈도우는 **1M 토큰**이고, claude.ai 챗에서는 Opus 5·Sonnet 5가 유료 플랜 전부에서 1M, 이전 세대(Opus 4.8·4.7·4.6, Sonnet 4.6)가 500K다. Claude Code는 이전 세대 Opus까지 1M을 쓴다.
  - 대상 3곳: `docs/index.md` 289행 참고 인용문, `slides/slides.md` 1365행 footer·1373행 발표자 노트.
  - 근거는 본문에 이미 걸려 있는 두 링크([Claude API 컨텍스트 윈도우](https://platform.claude.com/docs/ko/build-with-claude/context-windows)·[Claude.ai 컨텍스트 한도](https://support.claude.com/ko/articles/8606394))를 직접 받아 대조했다. 인용 출처는 그대로 유지한다.
  - 앞 항목이 이 서술을 대상 밖으로 적어 두었으나 사용자 지시로 뒤집혔다. 모델 버전 번호가 아니라 **한도 수치**를 고치는 별도 작업이다.

- **주간 한도 서술을 전체 모델 기준으로 통일** (2026-08-12 사용자 지시). 사용량 확인 안내의 주간 한도를 「Opus / 그 외 모델별」에서 「전체 모델 기준」으로 바꾼다. 근거는 모델별 한도 정책이 자주 바뀌어, 특정 모델 이름을 문서에 고정하면 금방 낡는다는 점이다.
  - 대상 2곳: `docs/intro.md` 151행 표 셀, `slides/slides.md` 763행 목록 항목.
  - **특정 모델의 별도 한도는 적지 않는다.** 갱신된 캡처에 「주간 · Fable」이 보이지만 같은 이유로 문서에 옮기지 않는다.
  - 갱신된 요약 화면에 새로 생긴 「컨텍스트 윈도우」 항목도 **설명을 추가하지 않는다**. Claude Code의 영역이라 이 페이지가 다룰 자리가 아니다.

- **사용량 화면 라벨·플랜 열거 정리** (2026-08-12 사용자 지시). 위 항목에 이어 사용량 확인 안내를 화면 표기에 맞춘다.
  - 세션 항목의 라벨을 화면 표기인 **「5시간 한도」**로 바꾼다(기존 「현재 세션 (Current session)」). 주간 한도도 같은 패턴으로 맞춰 영문 병기를 떼고 「사용한 양과 다음 재설정 시점」 문형으로 통일한다. 영문 병기를 빼는 근거는 캡처에 한국어 표기만 보여 영문 라벨을 확인할 수 없다는 점이다.
  - 라벨에서 「세션」이 사라지므로 `docs/intro.md` 176행의 「5시간 세션 초기화」도 「5시간 한도 초기화」로 맞춘다.
  - 한도가 있는 플랜 열거에 **Team을 더한다**(142행 「Pro·Max 플랜」 → 「Pro·Max·Team 플랜」).
  - 179행의 Claude Code `/usage` 안내는 **팀·엔터프라이즈 공식 문서를 더해 플랜 쌍을 맞춘다**. 링크가 하나뿐이라 플랜을 좁혀 적던 「Pro·Max 플랜 한도 사용량」을 「플랜 한도 사용량」으로 풀고, 두 문서를 목록 항목으로 나란히 둔다. 추가 문서는 [팀 또는 엔터프라이즈 플랜으로 Claude Code 사용하기](https://support.claude.com/ko/articles/11845131)이며, 원문에서 Team은 시트마다 Claude Code가 포함되고 월 포함 사용량을 쓰는 시트 기반(정액) 구조임을 확인했다.

- [ ] [D] 발행물과 이 이슈 작업 문서 전체에서 U+2014(EM DASH) 0건
  <details>
  <summary>검증 명령 ― repo 루트에서 실행, 출력 0건이면 통과</summary>

  ```bash
  EM=$(printf '\xe2\x80\x94')
  for f in $(find docs labs -name '*.md' -o -name '*.html' | sort) \
           slides/slides.md mkdocs.yml \
           $(find .ai/90_issues/active/issue-0050 -name '*.md' | sort); do
    n=$(grep -o "$EM" "$f" 2>/dev/null | wc -l | tr -d ' ')
    [ "$n" -gt 0 ] && echo "위반: $f (U+2014 ${n}건)"
  done; true
  ```

  - 설계 주의: 명령 안에 U+2014를 리터럴로 쓰면 이 spec 파일 자체가 검사 대상이라 **자기 위반**이 된다. `printf '\xe2\x80\x94'`(UTF-8 바이트)로 만들어 쓴다. `$'\u2014'` 형태의 유니코드 이스케이프는 macOS 기본 bash 3.2가 해석하지 못해 쓰지 않는다.
  - **작업 문서 표기 규칙**: spec·plan·summary에서 U+2014를 지칭할 때는 코드포인트 표기(`U+2014`)만 쓰고 문자를 직접 쓰지 않는다. 예시 문자열 안의 줄표는 U+2015로 적으며, 이는 문자 종류와 무관하게 「줄표가 있는 자리」를 가리킨다.
  - 이 항목이 통과하면 아래 두 산문 게이트의 검사 문자 중 U+2014 쪽은 공집합이 된다. 그래도 필터에서 빼지 않는다 ― 재유입을 잡는 것이 목적이다.
  </details>
- [ ] [D] 마크다운 대상 파일 전부에서 부제·기호 자리(제목·admonition 제목·링크 라벨·표의 해당 없음 기호·범례 행)를 걷어낸 뒤 잔존 줄표 0건
  <details>
  <summary>검증 명령 ― repo 루트에서 실행, 출력 0건이면 통과</summary>

  ```bash
  EM=$(printf '\xe2\x80\x94'); HB=$(printf '\xe2\x80\x95')
  for f in docs/index.md docs/intro.md docs/basics.md docs/labs.md \
           docs/operation-guide.md docs/security-guide.md \
           $(find labs -name '*.md' | sort) slides/slides.md; do
    n=$(sed -E "s/\[[^][]*\]\([^()]*\)//g; s/\|[[:space:]]*[$HB$EM][[:space:]]*/|/g" "$f" \
        | grep -vE '^#{1,6} |^[[:space:]]*(!!!|\?\?\?\+?) ' \
        | grep -vE '^[[:space:]]*(\*\*)?범례(\*\*)?:.*해당 없음' \
        | grep -c "[$HB$EM]")
    [ "$n" -gt 0 ] && echo "위반: $f ($n곳)"
  done; true
  ```

  - **두 문자를 모두 검사한다**(U+2015·U+2014). 한 문자만 찾으면 문자 전환 시점에 따라 검사 대상이 공집합이 되어 산문이 정리되지 않았는데도 통과한다 ― Task 3(문자 전환)과 Task 5·6(labs·slides 산문 정리)의 순서가 바뀌거나 일부만 전환된 중간 상태에서 그대로 발생하는 우회다.
  - 문자 클래스를 리터럴 `[…]`로 쓰지 않고 `$HB`·`$EM` 변수로 조립하는 이유: 이 spec 파일도 위 U+2014 0건 게이트의 검사 대상이라, 명령 안에 U+2014를 리터럴로 담으면 **명령 자체가 위반을 만든다**. sed 식을 큰따옴표로 감쌌지만 `\[`·`\(` 등은 셸이 그대로 통과시키므로 정규식 의미는 바뀌지 않는다.
  - 설계 주의: `sed` 1식이 인라인 링크(라벨 포함)를 통째로 제거해 링크 라벨 자리를, 2식이 표의 `| ― |`·`| ― (회사가 계약) |` 셀을 걷어낸다. `grep -v` 1식이 제목 행과 admonition 제목 행을, 2식이 범례 행을 제외한다. nav 라벨은 `mkdocs.yml`에 있어 검사 대상 파일에 없다.
  - 범례 예외(Task 0에서 추가): 표의 "해당 없음" 기호를 설명하는 행이라 줄표가 기호 자체를 지칭한다. 현재 `docs/security-guide.md` 193행·`slides/slides.md` 1760행 2곳에 해당하며, 패턴에 `해당 없음`을 함께 걸어 범례라는 낱말만으로 다른 행이 통째로 빠지는 과소 검출을 막았다.
  - 부 명칭("2부 ― 도구·데이터 연결")은 Task 0 실측 결과 전부 링크 라벨 안에 있어 `sed` 1식으로 걷힌다. 산문에 단독 등장하는 사례는 없으므로 별도 예외를 두지 않았다.
  - 표 셀 안 줄표는 Task 0에서 전환 자리로 확정했으므로 예외를 두지 않는다 ― `sed` 2식이 걷어내는 것은 셀 전체가 "해당 없음" 기호인 경우로 한정된다.
  - 마지막 `; true`는 루프 마지막 `[ ]` 판정의 종료 코드가 명령 전체를 실패로 만드는 것을 막는다 ― 합/불 판정은 종료 코드가 아니라 출력 0건 여부다.
  </details>

### 2026-08-12에 확정한 전제 (Task 3 사용자 점검 중 제기·질의·답변)

사용자가 Task 3 점검 중 "제목의 줄표는 의도한 것인가"를 물었고, 그 답을 확정하는 과정에서 **범위가 문자 통일까지 확장**됐다. 확정 경위와 근거는 아래와 같다.

- **부제 자리 줄표는 유지가 맞다**: 국립국어원 「문장 부호 해설」 제15항의 본항 용법이 정확히 이 자리다. 확인은 해설 PDF 원문을 직접 받아 조항 본문을 대조하는 방식으로 했다.
- **문자는 U+2015로 통일**: 규정은 코드포인트를 지정하지 않지만, 국립국어원 해설 원문이 U+2015를 쓴다(PDF 전체 U+2015 36회 대 U+2014 1회, 줄표 항 안에서는 U+2015만 12회, 조항 표제도 `15 줄표(―)`). U+2014는 영문 조판 문자로 한국어 규정 근거가 없다. 검토 후 버린 대안: U+2014 유지(문서 562건이 이미 일관하고 전환 비용이 없다는 이유로 구현 AI가 먼저 제시했으나, 한국어 관행 근거가 없어 사용자 지적으로 폐기).
- **기호 자리도 U+2015로 통일**: 표의 "해당 없음" 기호·범례·HTML 장식·인용 출처·페이지 표기 71건은 문장부호가 아니라 규정 소관 밖이지만 문자만 함께 통일한다. 근거는 두 문자가 화면에서 사실상 구분되지 않아 혼재하면 이후 작성 때 알아채기 어렵고, 검증 명령도 이중화된다는 점이다. 검토 후 버린 대안: 기호 자리는 U+2014 유지, 표 기호를 텍스트("해당 없음"·공란)로 교체.
- **#49 확정분 소급**: `docs/connect/` 3페이지와 `security-guide.md` 외부 연결 절의 제목·링크 라벨도 함께 전환한다. 링크 라벨은 대상 문서 제목을 반영하므로, 제목만 바꾸고 두면 같은 제목이 두 문자로 갈린다. 검토 후 버린 대안: 이번 범위 밖으로 두고 별도 이슈화.
- **삽입구 쌍 줄표도 없앤다**: 제4항 쉼표 [붙임 1·2]가 허용하는 용법이지만, 비개발자 대상 교육 문서에서는 괄호·문장 분리로 바꾼다. 기준을 「줄표 = 부제」 하나로 단순화하는 것이 목적이다. 현재 해당 후보는 `labs/step03-voca-quiz/stage2-voca-quiz-skill/README.md` 17행 1건이다. 검토 후 버린 대안: 규정 용법이므로 개별 판단해 유지.
- **작업 문서 3종 포함, `issue-workflow.md` 제외**: spec·plan·summary는 규칙을 정한 문서라 함께 전환한다. `issue-workflow.md`는 `issue-work` 스킬 템플릿의 사본이라 손대면 다음 스킬 실행 때 덮어써지므로 제외한다.
- **검증 필터는 두 문자를 모두 검사한다**: 산문 게이트가 한 문자만 찾으면 전환 시점에 따라 검사 대상이 공집합이 되어 통과한다. Task 3(문자 전환)을 산문 정리(Task 5·6)보다 앞에 두는 것과 별개로, 필터 자체에 `[――]`를 걸어 순서에 의존하지 않게 했다.
