- **audit 발견**: 0건

- **수행 내용 요약**: 사용자가 docs 점검 중 "제목에 줄표가 남은 것이 의도인가"를 물었고, 그 확인 과정에서 이슈 범위가 문자 통일로 확장됐다. 국립국어원 「문장 부호 해설」(2014) PDF 원문을 받아 조항을 직접 대조해 두 가지를 확인했다. ① 줄표의 규정 용법은 제15항(제목 뒤 부제의 **앞뒤**)과 제4항 쉼표 [붙임 1·2](삽입 어구의 **앞뒤**) 두 가지뿐이고 **둘 다 감싸는 형태**라, 「라벨 ― 부연」처럼 한쪽만 여는 형태는 규정에 없다. ② 해설 원문이 쓰는 문자는 U+2015다(PDF 89쪽 전체 U+2015 36회 대 U+2014 1회, 줄표 항 안에서는 U+2015만 12회, 조항 표제도 `15 줄표(―)`). 이에 따라 사용자 결정 3건(기호 자리 71건도 함께 통일 / #49 확정분인 2부 3페이지·security-guide 외부 연결 절 소급 / 규정이 허용하는 삽입구 쌍 줄표도 제거)을 받아 spec 「적용 기준」을 규정 근거·문자·부제 자리·산문 자리·기호 자리 5절로 재작성하고, 범위를 산문 대상과 문자 통일 대상으로 갈랐다. plan은 문자 전환을 **신설 Task 3**으로 산문 정리보다 앞에 배치하고 기존 Task 3~6을 4~7로 밀었다. 치환은 발행물 36개 파일 562건 + 작업 문서 3종 75건 = **637건**이며 U+2015 기존 사용은 0건이었다. 검증 5건 통과: U+2014 0건, 치환 총량 하한 충족(667건), docs 산문 게이트 0건, `mkdocs build --strict` 종료 코드 0, Slidev 빌드 종료 코드 0.
- **특이 사항**: 남은 완료 기준은 `[ND]` 글리프 육안 확인 1건이며 Task 4 사용자 점검에서 함께 받는다 ― 그래서 결과를 `부분 완료`로 두고 plan 체크박스도 비워 두었다. 검증 설계에서 걸린 함정 3건은 다음과 같다. ① **자기 위반**: 검증 명령의 문자 클래스에 U+2014를 리터럴로 담으면 spec·plan 자신이 「U+2014 0건」 게이트의 검사 대상이라 명령이 스스로 위반을 만든다. 실제로 치환 후 1건이 검출돼 `EM=$(printf '\xe2\x80\x94')` 바이트 조립 방식으로 바꿨고, 작업 문서에서는 U+2014를 코드포인트 표기로만 지칭하는 규칙을 spec에 남겼다. ② **공집합 우회**: 산문 게이트가 한 문자만 찾으면 전환 시점에 따라 검사 대상이 사라져 산문이 정리되지 않았는데도 통과한다. 두 문자를 모두 검사하도록 `"[$HB$EM]"`으로 고쳤다. ③ **삭제로 통과**: 「U+2014 0건」만으로는 문자를 지워도 통과하므로, 치환 총량 하한 검증을 완료 기준에 추가했다. 하한으로 둔 이유는 작업 문서의 줄표가 이슈 진행 중 계속 늘어 상한을 고정하면 spec 한 줄 수정마다 기준이 깨지기 때문이다.

  피드백 라운드 5 ― 「다른 컷」을 **「별개의 구분」**으로 교체했다(5곳). 영어 cut에서 온 표현이라 한국어 문서에서 낯설다는 사용자 지적이며, 이 repo가 표 머리글 「축」을 「구분」으로 바꾼 전례와 용어를 맞췄다. 대상은 `docs/basics.md` 87행 admonition 제목, `docs/index.md` 172행 3단계·결과물의 성격 연결 인용문, `slides/slides.md` 974행 본문과 564·978행 발표자 노트다. 「기준이 다릅니다」로 가지 않은 이유는 `basics.md` 88행 본문이 이미 「보는 기준이 다릅니다」로 풀어 주고 있어 제목과 본문이 같은 말을 반복하게 되기 때문이다. 제목이 별개임을 선언하고 본문이 이유를 설명하는 원래 구조를 유지했다. `slides/slides.md` 974행의 줄표는 Task 6에서 slides 전체를 일괄 정리할 자리라 손대지 않았다. 검증 3건 통과: 「컷」 잔존 0건, `mkdocs build --strict` 종료 코드 0, Slidev 빌드 종료 코드 0.

  피드백 라운드 7 ― 구어체 표현을 격식체로 정리했다(11곳). 시작은 `docs/basics.md` 68행 「하네스가 모델을 굴린 것」 지적이었고 「실행한 것」으로 바꿨다 ― 사용자 예시는 「실행시킨」이었으나 「실행하다」가 이미 타동사라 사동이 겹치고, #49에서 확정한 「서버·프로그램은 실행되다·위치하다」 원칙과도 같은 형태여서 「실행한」으로 정했다. 이어 75행 「설정한 나죠」의 어색함을 사용자가 제기했다. 제안은 「설정한 것이지요」였으나 그대로 두면 주어 「나」가 사라져 이 문단의 「회사 + 나」 대비가 무너지므로, 주체를 살린 「정한 건 회사고, 그 위에 설정한 건 나죠」 대구로 고쳤다. 여기서 범위가 문체 전반으로 확장됐다.

  전수 조사 결과를 세 유형으로 나눠 사용자 선택을 받았다: ① 종결어미 「-죠」 9곳 ② 대화체 되묻기 1곳 ③ 축약형 「게/건/걸」 15곳. 별도로 의문형 제목 14곳(「왜 AI 활용을 배워야 할까요?」 등)은 구어체가 아니라 절을 여는 질문 장치라 제외를 제안했다. 사용자가 **①+②만** 선택해 축약형 15곳과 의문형 제목 14곳은 유지했다. 반영은 `docs/index.md` 3곳(131·206·222행)·`docs/basics.md` 7곳(30·44·68·70·75행)·`docs/connect/index.md` 1곳(11행)이고, `slides/slides.md` 1105행은 `index.md` 206행과 같은 인용문이라 같은 회차에 맞췄다. 되묻기 자리(68행)는 「그럼 … 그 큰 부분은요? 그건 …」을 「그렇다면 … 무엇일까요? 그것은 …」으로 고쳤다 ― 「그건」은 축약형이라 원칙상 유지 대상이지만 앞 문장을 늘려 놓고 답을 짧게 받으면 어긋나 함께 풀었고, 같은 행의 「자율적인 게 아니라」는 유지 방침대로 두었다. 검증 3건 통과: docs 전체 「-죠/-지요/-은요?」 잔존 0건, `mkdocs build --strict` 종료 코드 0, Slidev 빌드 종료 코드 0.

  구어체 정리의 경계는 **동사 선택이지 문장 어미가 아니라는 점**을 사용자가 두 번에 걸쳐 확정했다. 68행 문단의 대화 톤 어미를 함께 정리할지 물었을 때 처음에는 「유지하고 넘어가자」였으나, 「나죠」 논의 후 「전반적으로 구어체를 찾아서 변경」으로 뒤집혔다. 최종 결과는 어미까지 격식체로 바꾸되 축약형·의문형 제목은 남기는 선이다.
