  **6차 audit(재감사, 2026-08-02)**: 사용자가 같은 모델로 5차 보정 후 재감사를 수행해 리포트를 갱신했다. 종합 판단 **"충족"**, 1단계 PASS 15·PARTIAL 0·FAIL 0, 2단계 발견 2건(F-1 낮음, F-2 정보). 5차 F-1·F-2는 해소, F-3은 **대부분 해소**(표·SSoT는 정합화됐으나 같은 페이지 경고문 한 문장이 남아 이번 F-1로 분리). 3~5차 내내 중간 위험으로 반복되던 용어 계열 지적이 처음으로 0건이 됐고, 1단계 부분 충족도 처음으로 0건이 됐다. `--response` 검토에서 1단계 발견 0건이라 순서 게이트가 열린 상태로 2단계 F-1만 승인받았다. **보정 1건**(F-1 → Task 6), F-2는 앞 회차와 같이 사용자 완료 게이트 안내라 보정 대상에서 제외했다.

- **특이 사항**: 1차 보정 후 spec `[D]` 검증 명령 전부 재실행 통과, `--strict` 빌드 종료 코드 0. audit이 인용한 GitHub 문서(claude.com/docs)와 본문이 링크한 서포트 아티클(10167454)은 같은 「GitHub에서 추가」 기능을 다루는 문서로 확인돼, 쟁점의 원인은 서술 오류가 아니라 링크 배치였다.
  2차 보정에서는 공식 문서 원문을 직접 내려받아 대조했고(지원문서 11176164·11725091, `claude.com/docs/connectors/verification`), **audit의 사실 지적은 3건 모두 성립하되 권고안 2건에는 반론**을 세워 축소 반영했다 — F-1의 "일반 사용자에게 제어 수단 없음"은 공식 문서 문장의 범위를 넘는 해석이고, F-2의 "3경로 재편"은 같은 공식 문서의 "디렉토리는 카탈로그일 뿐"이라는 서술과 어긋난다(각 근거는 Task 4·5 블록). 보정 후 재검증 통과 — spec `[D]` 5종 전부, `--strict` 빌드 종료 코드 0, `git diff --check main...HEAD` 위반 0건, 새로 건 앵커 `#vs-connector` 실재 확인.
  3차 보정에서는 audit이 인용한 문장을 전부 원문에서 직접 확인했고, **사실 지적 3건은 모두 성립하되 권고안 2건에는 다시 반론**을 세워 축소 반영했다 — F-1의 3시점 구조 신설은 비개발자 페이지에 새 개념 층을 더하는 비용이 과하고, F-2의 표기 축 교체는 spec 전제의 「사용자 지정 내용 축」을 바꾸는 저자 결정 사항이라 audit이 단독 확정할 사안이 아니다(각 근거는 Task 6·5 블록). F-3은 ADR-0010 리스크 완화 조항과 정확히 맞물려 그대로 수용하되, docs 최초의 영문 외부 링크가 되므로 ADR에 예외 조항을 병기했다. 보정 후 재검증 통과 — spec `[D]` 5종 전부, `--strict` 빌드 종료 코드 0, `git diff --check main...HEAD` 위반 0건, 추가한 외부 링크 HTTP 200, F-1·F-2 잔존 배타 표현 스캔 0건(`security-guide.md:132`은 이제 핵심 원칙 박스와 정합해 의도된 존치).
  4차 보정에서는 audit이 지목한 충돌 지점을 원문에서 직접 대조했고, **사실 지적 2건 성립·1건 반론**으로 갈렸다 — F-1의 내부 충돌은 실재하나 권고안(용어 3분할)은 spec 전제의 내용 축을 바꾸는 저자 결정이라 한정 기준만 교체하는 축소안으로 처리했고, F-2는 공식 한국어 문서에서 3종 모드를 확인해 그대로 수용했으며, F-3은 공식 문서가 Verified·Community에만 화면 표시를 명시하고 Custom에는 표시 서술이 없어 **audit 근거가 약하다는 반론**이 성립했다(표현 정밀화만 반영). 3차 보정이 4차 발견을 만든 연쇄였던 만큼 이번에는 분류 기준의 혼선 자체를 제거해 같은 계열의 재발 여지를 닫았다. 보정 후 재검증 통과 — spec `[D]` 5종 전부, `--strict` 빌드 종료 코드 0(문서 관련 경고 0건), `git diff --check main...HEAD` 위반 0건, 추가한 한국어 공식 링크 HTTP 200, 상호 링크 4건·1건 유지, 「MCP 서버」 정의 문맥의 잔존 충돌 표현 스캔 0건(절차 문맥 3건은 의도된 존치).
