## Task별 수행 결과

### Task 1: 메시지 프레임 정합 검토 — ADR-0005 §3와의 관계 정리

- **결과**: 완료
- **수행 내용 요약**:
  - ADR-0005 §3 ("결정성/비결정성은 결과형으로 우회 전달") 재독. 현재 `docs/index.md` L145–186 "매번 시키기 vs 소프트웨어로 만들기" 박스가 이 원칙을 충실히 따르고 있음 — "매번 결과가 조금씩 다름"·"동일 품질로 반복 보장" 등 **결과형 표현**만 사용, "비결정"이라는 단어 자체는 본문에 부재.
  - Issue #40 요구사항을 ADR-0005 §3와 대조: "결정 vs 비결정 차이를 알려준다" + "기본적으로 비결정적이라는 점을 인지시킨다"는 **메커니즘 단어의 명시적 도입**을 요구 → §3 원칙과 정면 충돌.
  - ADR-0001 3단계 모델(챗봇 → 프롬프트 재활용 → 에이전트)과 Issue #40 비교 3종(1회성 프롬프트 / 에이전트 스킬 / 애플리케이션)의 차원 차이 확인:
    - ADR-0001 = **학습자의 활용 수준 사다리** (1단계→3단계로 올라감)
    - Issue #40 = **결과물의 형태·체계화 수준** (1회성 ↔ 스킬 ↔ 애플리케이션)
    - 두 분류는 부분 겹치지만 동일하지 않음. "애플리케이션"은 ADR-0001 3단계 바깥에 있는 **비교 기준** — 학습자가 "내가 만드는 스킬"의 위치를 두 끝점 사이에서 인지하게 하는 장치.
  - **처리 방향 결정: (B) 신규 ADR + ADR-0005 §3 후속 변경 노트**
    - 신규 ADR (가제): "결정성/비결정성 메커니즘의 명시적 가시화 — 비교표 형태로 도입". ADR-0005 §3의 기본 원칙(본문 결과형)은 유지하되, 비교표 1곳에 한해 메커니즘을 직접 명시.
    - ADR-0005 §3에는 후속 변경 노트 추가: "본문 기본은 여전히 결과형, 비교표 1곳만 메커니즘 명시"로 운용 변경.
    - ADR-0001은 본문 변경 없음. 단 신규 ADR에서 "Issue #40 3종은 ADR-0001 3단계와 다른 차원"임을 명시.
  - 신규 ADR 작성과 ADR-0005 후속 변경 노트는 Task 5에서 처리.
- **특이 사항**:
  - (C) 결과형으로만 비교표 구성 안 검토 → 이슈 본문 명령("차이를 알려준다", "비결정적이라는 점을 인지시킨다")과 직접 충돌하므로 기각.
  - (A) ADR-0005에 단순 후속 변경 노트만 추가 안 검토 → "§3 원칙 유지 + 비교표만 예외"라는 운용은 자체로 일관성이 약해, 결정을 신규 ADR로 격상하는 것이 정직.
  - 신규 ADR 작성 시점에서 ADR-0005 §3 노트와 짝으로 처리. 두 ADR이 모순되지 않도록 같은 PR에서 묶어 갱신.
