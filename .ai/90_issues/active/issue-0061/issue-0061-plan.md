### Task 2: docs effort 절 작성

- [x] 완료
- **목표**: `docs/intro.md`에 effort 절을 새로 두어 정의, 공통 5단계, 시간 서술, 모델별 기본값, 주의 사항, 사용량 연결을 담는다.
- **대상 요구사항**: R1, R2, R3, R4, R5, R6
- **작업 내용**:
  1. `#claude-models` 절의 버전 안내 인용문(`> 라인업은 …`) 뒤 `---` 다음에 `### <제목> { #claude-effort }` 절을 둔다 (A1). 뒤에는 `---`를 두어 `#claude-ai` 절과 나눈다.
  2. 첫 문단에서 effort를 정의한다. 모델 선택(누가 하느냐)과 별개로 같은 모델이 얼마나 공들이느냐를 정하는 조절 장치이고, 단계를 올리면 확인과 예외 상황 점검이 늘어난다. Task 0에서 비유를 쓰기로 했으면 참고 글의 비유를 출처와 함께 둔다.
  3. 단계 표를 둔다. 첫 칸은 `` `low` ``~`` `max` `` 다섯 행을 이 순서로, 둘째 칸은 spec R2의 단계별 기준 설명(low의 「쉬운 문제는 생각을 건너뛰기도 함」 포함)을 쉬운 말로 옮긴 설명이다. 공식 표 「설명」 열과 어긋나지 않게 하고, 작업 유형 추천은 넣지 않는다 (A2, R2·R3). `xhigh` 설명에는 「30분 이상 걸리는 긴 작업」을 쓴다. 다른 행에는 시간값을 쓰지 않는다 (R4).
  4. 표 아래에 OpenAI 한 줄(「OpenAI에는 이보다 낮은 단계(`none` · `minimal`)도 있습니다」 꼴)을 둔다.
  5. 시간 서술을 둔다. 「같은 일이라도 단계를 올리면 더 오래 걸리고 사용량도 늘어난다」와 참고 글 예시 1건(low 약 2분, 높은 단계 약 33분, Claude Code 기준)을 출처 링크와 함께 둔다 (R4, A4).
  6. 모델별 기본값을 둔다. Fable 5.1 `high`, Opus 5.5 `medium`, Sonnet 5.5 `high`, Haiku 4.5 미지원을 같은 행에 모델과 값이 오도록 쓴다 (R5, A3). Task 1에서 앱 기본값이 다르게 확인됐으면 구분해 적는다.
  7. 주의 사항 세 가지를 tip이나 note 카드로 둔다: 모델마다 지원 단계·기본값이 다름, 같은 이름이라도 생각하는 양이 다름, effort는 정확한 상한이 아니라 공들이는 정도를 알리는 신호.
  8. Task 0 확정에 따라 사용량 절(`#claude-usage`)과 연결한다 (R6). Task 1에서 확인한 화면 표기를 해당 위치에 그대로 쓰고, 공식 문서 링크(`/ko/`)를 둔다 (R7, A14).
