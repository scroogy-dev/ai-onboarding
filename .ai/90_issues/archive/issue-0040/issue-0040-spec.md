# Issue #40 스펙 — 이론 자료 보강 (결정성 · 비결정성 · 형태별 비교표)

> 원본: https://github.com/scroogy-dev/ai-onboarding/issues/40

## 목표 (Goal)

생성형 AI가 본질적으로 비결정적이라는 점을 비개발자 학습자에게 인지시키고, **1회성 프롬프트 · 에이전트 스킬 · 애플리케이션** 세 형태가 결정성/비결정성·기타 기준에서 어떻게 다른지 한눈에 비교할 수 있는 자료를 docs(SSoT)와 slides 양쪽에 보강한다.

---

## 범위 (Scope)

**포함 (In)**

- "결정 vs 비결정"의 의미를 비개발자 친화 자연어로 풀어내는 본문 — 메커니즘 깊이는 최소화하되, "왜 매번 답이 다를 수 있나"의 결과 현상은 학습자 경험에 연결한다
- "생성형 AI는 기본적으로 비결정적이다"라는 점을 단정적으로 명시
- **1회성 프롬프트 vs 에이전트 스킬 vs 애플리케이션** 비교표
  - 결정성/비결정성 축
  - 그 외 학습자가 의사결정에 쓸 수 있는 축 (반복성·일관성·만드는 비용·언제 적합한가 등 — 최종 축은 plan에서 확정)
  - 각 형태의 장단점·언제 써야 하는지 결정 가이드
- docs(SSoT) 본문 반영 — 위치는 plan에서 확정 (후보: `docs/basics.md` 기본 용어 카드 근처, 또는 `docs/intro.md`의 N-2 사다리/W3 박스 근처)
- slides 반영 — ADR-0002에 따라 SSoT 메시지를 슬라이드 매체 문법으로 재가공
- ADR-0005 §3(결과형 우회 전달 원칙)과의 관계 정리 — 본 이슈는 메커니즘을 정직하게 가시화하는 방향이므로 ADR 후속 변경 또는 신규 ADR 검토가 필요할 수 있음 (plan Task 1에서 판단)

**비포함 (Out)**

- LLM 내부 동작(샘플링·temperature·확률 분포 등) 기술 메커니즘의 깊은 설명 — 비개발자 친화 깊이를 넘는 부분
- 새 실습(labs) 추가 — 본 이슈는 이론 자료에 한정
- 보안·운영 가이드 측 반영 — 본 이슈 범위 밖
- 강의 톤/순서 전면 재배치 — 기존 인용·박스·사다리 구조는 유지하고 보강만 한다

---

## 완료의 정의 (Definition of Done)

- [ ] "결정 vs 비결정" 개념이 비개발자 친화 자연어로 docs에 1회 이상 명시되어 있다
- [ ] "생성형 AI는 기본적으로 비결정적이다"라는 메시지가 docs와 slides 양쪽에 단정적으로 박혀 있다
- [ ] 1회성 프롬프트 · 에이전트 스킬 · 애플리케이션 3종을 비교하는 표가 docs에 존재하고, 결정성/비결정성 축을 포함해 최소 3개 이상의 축으로 비교된다
- [ ] 비교표 또는 그 요약이 slides에도 반영되어 있다 (슬라이드 매체에 맞게 축약 가능)
- [ ] ADR-0005 §3와의 관계가 정리되어 있다 — ADR 보완 또는 신규 ADR 작성 결정이 plan/summary에 명시되어 있다
- [ ] 비개발자 친화 톤 유지 — 전문 용어 최소화, 결과형 표현 우선 ([[feedback_non-developer-actionable-depth]] 준수)
- [ ] MkDocs 빌드 및 Slidev 빌드(또는 export) 시 새 콘텐츠가 에러 없이 표시된다
