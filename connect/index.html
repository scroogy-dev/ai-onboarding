    2부 개요 — 연결이 왜 필요한가¶

    1부에서 만난 에이전트가 내 컴퓨터 밖의 자료와 도구까지 다루게 하는 이야기입니다. 새로운 단계가 아니라, 1부에 이어서 AI가 쓸 수 있는 자료의 범위를 넓히는 내용입니다.

    1부에 이어서 진행됩니다¶

    1부의 AI 활용 3단계는 내가 AI를 얼마나 활용하는가를 아래에서 위로 쌓아 올린 사다리였습니다. 3단계(에이전트 활용)에 이르면 AI가 내 폴더의 파일을 직접 열고 작업합니다.

    그런데 거기서 한 가지가 걸립니다. 일에 필요한 자료가 그 폴더 안에만 있지는 않다는 것이죠. 회의록·규정·기획서는 Confluence에, 업무 요청과 진행 상황은 Jira에 있습니다. 에이전트가 아무리 잘 움직여도 볼 수 있는 자료가 내 컴퓨터 안으로 제한되면, 할 수 있는 일도 거기서 멈춥니다.

    연결은 1부 3단계와 나누는 기준이 다릅니다

    3단계는 내가 AI를 얼마나 활용하는가(활용 수준)를 기준으로 나눈 단계이고, 연결은 AI가 어떤 자료까지 쓸 수 있는가(자료의 범위)를 정하는 일입니다. 기준이 다르므로 단계가 하나 더 늘어나는 게 아니라, 지금 단계 그대로 쓸 수 있는 자료가 넓어집니다.

    그래서 2단계에 있어도 연결은 쓸 수 있고, 3단계에 있어도 연결 없이 로컬 파일만 다룰 수 있습니다. 순서가 아니라 선택입니다.

    무엇이 달라지나요¶

    같은 일을 연결 전후로 놓고 보면 차이가 분명합니다.

    연결하기 전

    회의록을 요약하려면 Confluence에서 문서를 찾아 열고, 본문을 복사해 대화창에 붙여넣습니다.

    자료가 세 건이면 이 과정을 세 번 반복하고, 다음 주에 또 반복합니다.

    연결한 뒤

    "지난주 팀 회의록을 찾아 결정사항만 정리해줘"라고 부탁하면 AI가 직접 찾아 읽습니다.

    붙여넣는 단계가 사라지고, 매주 같은 부탁을 그대로 쓸 수 있습니다.

    연결이 늘려 주는 것은 AI가 볼 수 있는 자료의 범위입니다. 무엇을 시킬지 정하고 결과가 맞는지 확인하는 일은 그대로 사람에게 남습니다. 오히려 AI가 스스로 읽어 온 자료는 내가 직접 붙여넣은 자료와 달리 무엇을 읽었는지 내가 보지 못한 채 결과만 받게 되기 쉽습니다. 그래서 메타 원칙 ③ AI 결과물 검토·이해 의무는 연결한 뒤에 더 중요해집니다. 요약을 받았다면 어느 문서에서 나온 이야기인지 함께 물어 짚어 보세요.

    연결하는 방법은 두 갈래입니다¶

    용어는 1부에서 이미 정의했습니다

    외부 컨텍스트와 MCP가 무엇인지는 1부 기본 용어와 범위 — 외부 컨텍스트에 정리돼 있습니다. 2부는 그 정의를 그대로 가져다 쓰고 다시 정의하지 않습니다. 단어가 낯설다면 그 절을 먼저 한 번 읽고 오세요.

    아래 두 갈래는 모두 MCP 위에서 동작합니다. 갈리는 것은 기술이 아니라 찾아서 등록하는 방법이고, 2부에서 「MCP 서버」라고 할 때는 그중 기본 커넥터 목록에 준비돼 있지 않은 쪽을 가리킵니다.

    구분 기본 커넥터 MCP 서버
    무엇인가 Claude가 미리 준비해 둔 목록에서 고르는 방식 그 목록에 없는 도구·자료를, 공개된 연결 통로를 직접 찾아 등록해 쓰는 방식
    연결 절차 서비스 선택 → 로그인 → 권한 확인 → 승인 서버 선택 → 등록 → 권한 확인 → 승인
    고를 수 있는 폭 준비된 서비스 (Atlassian·GitHub 등) 훨씬 넓음 (준비되지 않은 도구까지)
    내가 판단할 것 어떤 권한을 넘길지 어떤 권한을 넘길지 + 이 서버를 믿을 수 있는지
    자세히 보기 기본 커넥터 — Atlassian·GitHub MCP 서버 이용하기

    고르는 순서는 간단합니다. 필요한 서비스가 커넥터 목록에 있으면 커넥터로 충분합니다. 목록에 없을 때 MCP 서버를 봅니다. 편의와 판단 부담이 정확히 반대 방향이라, 굳이 어려운 쪽부터 갈 이유가 없습니다.

    명령줄 도구로 연결하는 방법은 여기서 다루지 않습니다

    이 두 갈래 밖에도, gh(GitHub CLI)처럼 컴퓨터에 설치해 두고 명령어로 쓰는 개발자 도구를 통해 외부 서비스를 연결하는 방법이 있습니다. 개발자 영역이라 2부에서는 논외로 합니다.

    제품마다 연결 지원 범위가 다릅니다

    같은 Claude라도 claude.ai·Cowork·Code가 다룰 수 있는 연결의 폭이 다릅니다. 어느 제품에서 무엇이 되는지는 1부 도구와 제품 — 기능 비교 표에 정리돼 있습니다.

    시작하기 전에¶

    준비물

    • 이 교육은 유료 플랜을 기준으로 진행합니다. 1부 준비사항과 같은 기준이며, 실습 도구(Claude Cowork·Code)를 쓰기 위한 조건입니다. 개인은 Pro 이상 개인 플랜, 임직원은 회사가 계약한 Team·Enterprise 플랜으로만 진행합니다. 회사 업무·자료를 개인 플랜에서 다루는 것은 무료·유료를 가리지 않고 회사 보안 정책 위반입니다.
    • 연결할 서비스의 계정은 평소 쓰던 Jira·Confluence 계정을 그대로 씁니다. 새로 만들 필요는 없습니다.
    • 회사 환경이라면 관리자 정책을 확인하세요. 조직에 따라 쓸 수 있는 연결이 미리 정해져 있거나 별도 승인이 필요할 수 있습니다. 목록에 서비스가 보이지 않는다면 권한 문제일 수 있으니 담당 부서에 먼저 확인하세요.

    연결하면 AI가 자료를 직접 가져오고 남깁니다

    자료를 일일이 붙여넣지 않아도 되는 만큼, AI가 접근할 수 있는 범위도 함께 넓어집니다. 승인 화면에서 무엇을 허용하는지 읽고 넘기세요. 회사 자료가 오가는 연결이라면 사내 정책 확인이 먼저입니다. 지켜야 할 기준은 보안 및 개인정보 가이드 — 외부 연결에 정리돼 있습니다.

    이 시리즈가 다루는 선¶

    이용까지 다루고, 만드는 일은 다루지 않습니다

    다룹니다: 커넥터를 연결하고 끊는 절차, 승인 화면에서 확인할 것, MCP 서버를 고르고 등록하는 방법, 잘 안 될 때 확인할 것.

    다루지 않습니다: MCP 서버를 직접 만드는 일(개발자 영역이라 포인터만 남깁니다), RAG의 내부 구조·구현 패턴.

    1부와 같은 기준입니다. 비개발자가 고르고·연결하고·정하는 일까지가 이 시리즈의 범위입니다 (→ 기본 용어와 범위 — 에이전트 = 모델 + 하네스).

    읽는 순서¶

    1. 기본 커넥터 — Atlassian·GitHub 부터 시작하세요. 문턱이 가장 낮은 방법이고, 대부분의 업무 자료는 여기서 해결됩니다.
    2. MCP 서버 이용하기 는 커넥터 목록에 없는 도구가 필요할 때 봅니다.

    두 페이지 모두 본인이 실제로 쓰는 서비스 하나를 정해 두고 읽으면 훨씬 잘 붙습니다. 1부에서 고른 반복 작업이 있다면, 그 작업이 어떤 자료를 필요로 하는지부터 떠올려 보세요.
